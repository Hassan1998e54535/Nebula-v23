NEXUS reads its settings from environment variables. They are in a file named `.env`, in the same directory as `docker-compose.yml`.

The installer in [Get started](/operator/get-started/) writes `.env` and fills in every secret. Start with [Core identity and public address](#core-identity-and-public-address) and [Secrets you must generate](#secrets-you-must-generate).

## How configuration is loaded

Compose forwards every setting a self-hosted instance can change from `.env` to each service that reads it. Where the stack needs a value other than the built-in default, Compose sets one and the entry below names it. Any other forwarded name that `.env` leaves out reaches its service empty, and the service applies its built-in default.

[Keys Compose does not forward](#keys-compose-does-not-forward) lists the names `.env` cannot set.

Single-quote values containing a literal `$` so Compose does not expand them as variable references:

```ini
POSTGRES_PASSWORD='ab$cd'
```

A container's environment is fixed when it is created. Apply changes with `docker compose up -d`, which recreates affected services. `docker compose restart` keeps the old environment.

Precedence, highest first:

1. A value stored by the admin dashboard, for the settings listed under [Runtime settings](#runtime-settings-in-the-admin-dashboard).
2. The environment variable.
3. The built-in default.

Use `true` or `false` for booleans, decimal integers for integer settings, and the specified object or array for JSON settings. Defaults and accepted values are listed below. Every service built from this version of the stack files or later reads an empty or blank value the same as an unset one, so an empty value restores the default. Older images do not, which [Match the images to the stack files](/operator/upgrading/#match-the-images-to-the-stack-files) covers.

### Reading a secret from a file

Any setting a NEXUS service reads for its configuration can come from a file instead, such as a Docker secret. Set the variable's name with `_FILE` appended to the file's path, and leave the variable itself empty. The service reads the file at startup and drops one trailing newline. Startup fails, naming both variables, when the variable and its `_FILE` form are both set. It also fails, naming the path, when the file is missing, unreadable or not valid UTF-8. The name to use is the one the service sees, so `POSTGRES_PASSWORD` in `.env` becomes `NEXUS_POSTGRES_PASSWORD_FILE`.

Add the secrets through a local Compose override. `NEXUS_SUDO_MODE_SECRET` is read by `api` and `worker` only:

```yaml
secrets:
  sudo_mode_secret:
    file: ./secrets/sudo_mode_secret

services:
  api:
    secrets: [sudo_mode_secret]
    environment:
      NEXUS_SUDO_MODE_SECRET: ''
      NEXUS_SUDO_MODE_SECRET_FILE: /run/secrets/sudo_mode_secret
  worker:
    secrets: [sudo_mode_secret]
    environment:
      NEXUS_SUDO_MODE_SECRET: ''
      NEXUS_SUDO_MODE_SECRET_FILE: /run/secrets/sudo_mode_secret
```

Compose still checks the required names in `.env` before it applies the override, so keep a placeholder value there. Every NEXUS service gets the same shared settings, so a secret several services read, such as `NEXUS_POSTGRES_PASSWORD`, needs the same two entries on each of them: `api`, `worker`, `gateway`, `media-proxy`, `push`, `admin`, and `snowflakes`, `users`, `gifs`, `messages` and `unfurl` with their `-shard` services. Any service left out keeps the placeholder. The secret file must be readable by the user the container runs as.

The bundled backing containers read their own settings. The `postgres` container takes `POSTGRES_PASSWORD: ''` and `POSTGRES_PASSWORD_FILE` in its own `environment`, and on a fresh volume it creates the database with that password. `seaweedfs-init`, `meilisearch` and `livekit` have no `_FILE` form, so a file-based S3, Meilisearch or LiveKit secret still needs its real value in `.env` for them. `NEXUS_ENV`, `LOG_LEVEL`, `NEXUS_DISABLE_RATE_LIMITS` and the `NEXUS_ERLANG_*` settings other than `NEXUS_ERLANG_COOKIE` are read directly, so set them as plain values.

## Core identity and public address

`NEXUS_DOMAIN` is required. Everything else here is optional.

| Variable | Value in `.env.example` | Controls |
| --- | --- | --- |
| NEXUS_DOMAIN | `chat.example.com` | The hostname users type. Reaches services as `NEXUS_BASE_DOMAIN`. Compose refuses to start when it is unset or empty |
| NEXUS_PUBLIC_SCHEME | `https` | The scheme users see. Must be `http` or `https`. Anything else fails startup |
| NEXUS_PUBLIC_PORT | `443` | The port users see. Integer. Omitted from derived URLs when it is the default for the scheme |

Outside Compose these fall back to an empty base domain, `http`, and port `8088`. Compose supplies `https` and `443`.

The API and worker require hostname-only domain settings: no scheme, port, credentials, path, query, fragment, or whitespace. Bracket IPv6 addresses. Valid hostname spelling is preserved, including case and a terminal root dot.

`NEXUS_DOMAIN` also feeds the default passkey relying party identifier, the default VAPID contact address, and the edge listener address.

`NEXUS_PUBLIC_ORIGIN` states the same public address as one string, and [The public origin](#the-public-origin) has it.

## Secrets you must generate

Every value below ships as `CHANGE_ME`, and the installer generates them all. To set one by hand or rotate it, generate it with `openssl rand -hex 32` unless its entry names another command. Compose refuses to start when one is unset or empty, and names the variable.

#### `POSTGRES_PASSWORD`

The database login, reused as `NEXUS_POSTGRES_PASSWORD`. Requires changing the stored role password too.

#### `MEILI_MASTER_KEY`

The Meilisearch master key, reused as `NEXUS_SEARCH_API_KEY`. Recreate `meilisearch` and every service that searches.

#### `NEXUS_S3_SECRET_KEY`

The object-storage secret, reused as `NEXUS_S3_SECRET_ACCESS_KEY`. `seaweedfs-init` installs it as the object store's only S3 identity on every `compose up`, so a changed value takes effect on the next start.

#### `NEXUS_SUDO_MODE_SECRET`

Sudo mode JWTs, as a raw HS256 key. Changing it ends every active sudo mode session.

#### `NEXUS_CONNECTION_INITIATION_SECRET`

Connection initiation tokens and harvest download links. Changing it invalidates connection initiation tokens not yet verified and harvest download links already issued.

#### `NEXUS_PROFILE_PSEUDONYM_SECRET`

Derives the stable placeholder name and tag that other users see while an account's profile is hidden. Must be byte-identical on `api`, `worker`, and `users-shard`, or the same account shows two different names. Changing it gives every hidden profile a new placeholder. `api` and `worker` refuse to start without it when `NEXUS_ENV` is `production`. `users-shard` refuses to start without it unless `NEXUS_ENV` is `development` or `test`.

#### `NEXUS_GATEWAY_RPC_AUTH_TOKEN`

Internal RPC between the API and the Gateway. Must be byte-identical on `api`, `worker`, and `gateway`.

#### `NEXUS_MEDIA_PROXY_SECRET_KEY`

Media Proxy URLs. Must match across `api`, `worker`, `media-proxy`, `gifs`, and `unfurl`.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_SECRET_BASE64`

Generate with `openssl rand -base64 32`. [Upload relay](/media-proxy/upload-relay/) capability tokens. Must be standard base64 decoding to at least 32 bytes. Must match on `api`, `worker`, and `media-proxy`. `api` and `worker` refuse to start without it in every mode. `media-proxy` refuses to start without it when `NEXUS_MEDIA_PROXY_MODE` is `upload` or `relay`.

#### `NEXUS_MEDIA_PROXY_ATTACHMENT_URL_SECRETS_BASE64`

Generate each entry with `openssl rand -base64 32`. Signs the [attachment URLs](/media-proxy/overview/#signed-attachment-urls) NEXUS returns. A comma-separated list, where each entry must be standard base64 decoding to at least 32 bytes. Spaces around an entry and empty entries are ignored. The first entry signs and every entry verifies. Must match on `api`, `worker`, and `media-proxy`, and must differ from `NEXUS_MEDIA_PROXY_SECRET_KEY`. `api` and `worker` refuse to start when an entry is invalid, and with no entry they return unsigned URLs. `media-proxy` reads it only when `NEXUS_MEDIA_PROXY_MODE` is `mp` or `upload`, and then refuses to start with an invalid entry, or with no entry when `NEXUS_MEDIA_PROXY_ATTACHMENT_SIGNATURE_MODE` is `report` or `enforce`.

Compose forwards it from `.env` and passes it empty when unset, so a self-hosted instance returns unsigned URLs until an operator sets one. Setting it alone changes nothing on the read side, because `NEXUS_MEDIA_PROXY_ATTACHMENT_SIGNATURE_MODE` stays `off` until it is set too.

Rotate it in three steps, and apply each one with `docker compose up -d` before starting the next:

1. Add the new secret as the second entry. Every `media-proxy` then accepts it before any service signs with it.
2. Move the new secret to the first entry, so it signs.
3. Remove the old secret no sooner than one day after step 2, because an ordinary URL it signed stays valid for up to a day.

A [data package URL](/http-api/messages/#data-package-attachment-urls) inside a harvest export never expires, so removing a secret ends every data package URL it signed at once, including the links inside exports already delivered, and those exports have to be rebuilt. Step 3 is safe for ordinary URLs alone.

#### `NEXUS_ADMIN_SECRET_KEY_BASE`

Admin sessions, CSRF tokens, and OAuth state. Changing it signs every admin out. The admin service refuses to start when it is empty.

#### `NEXUS_ADMIN_OAUTH_CLIENT_SECRET`

The admin OAuth2 client secret. The API requires a non-empty value to serve the admin application.

#### `NEXUS_ERLANG_COOKIE`

The BEAM distribution secret. Only the Gateway reads it. Rotate it on every Gateway node at once when clustering.

#### `LIVEKIT_API_SECRET`

LiveKit access tokens. Must be at least 32 characters.

#### `NEXUS_VAPID_PUBLIC_KEY`

Base64url of the 65-byte uncompressed P-256 point, unpadded, which is 87 characters. Config validation rejects any other shape at boot. `install.sh` derives it with `openssl ecparam` and `openssl ec`, and `npx web-push generate-vapid-keys` produces the same pair.

#### `NEXUS_VAPID_PRIVATE_KEY`

The matching half of the pair. Base64url of the 32-byte P-256 scalar, unpadded, which is 43 characters. The API refuses to start when the scalar does not derive the public point. Both values are required even when nobody uses browser notifications.

The values below ship with a usable value. Both are required.

#### `NEXUS_S3_ACCESS_KEY`

`.env.example` `nexus`. The object-storage access key. Reaches services as `NEXUS_S3_ACCESS_KEY_ID`, which config validation requires to be non-empty.

#### `LIVEKIT_API_KEY`

`.env.example` `nexus`. The LiveKit API key. Compose passes it to LiveKit as `LIVEKIT_KEYS` and as the webhook signing key, and to the API as `NEXUS_LIVEKIT_API_KEY`, so one change in `.env` moves them all.

## Endpoint derivation from NEXUS_BASE_DOMAIN

NEXUS builds its public endpoints from the scheme, the base domain, and the port. A port of `443` under `https` or `wss`, or `80` under `http` or `ws`, is omitted.

| Endpoint | Derived value |
| --- | --- |
| api, api_client | scheme, base domain, optional port, `/api` |
| app | scheme, base domain, optional port |
| gateway | `ws` or `wss`, base domain, optional port, `/gateway` |
| media | scheme, base domain, optional port, `/media` |
| static_cdn | scheme, base domain, optional port. With `NEXUS_STATIC_CDN_DOMAIN` set it becomes `https://` and that domain, with no port |
| admin | scheme, base domain, optional port, `/admin` |
| marketing | scheme, base domain, optional port, `/marketing` |
| invite | scheme, `NEXUS_INVITE_DOMAIN` or the base domain, optional port, `/invite` |
| gift | scheme, `NEXUS_GIFT_DOMAIN` or the base domain, optional port, `/gift` |

Nothing in the stack reads `X-Forwarded-Proto` or `X-Forwarded-Host`. Every absolute URL comes from configuration, so set the scheme, the host, and the port by hand and keep them in sync with whatever terminates TLS.

## The public origin

`NEXUS_PUBLIC_ORIGIN` states the public address as one string. It holds the scheme, the host, and the port when that port is not the default for the scheme. Leave it unset unless you need it. Compose otherwise derives every public URL from `NEXUS_PUBLIC_SCHEME`, `NEXUS_DOMAIN` and `NEXUS_PUBLIC_PORT`, non-default ports included.

When set, it must agree with those three. A mismatch can break sign-in, setup, passkeys and media access.

Use an explicit `http://` or `https://` origin. Surrounding spaces and a single trailing slash are accepted. Credentials, paths, query strings, fragments, control characters, and empty or zero ports are rejected.

## Endpoint overrides

Each of these replaces its derived endpoint wholesale. Set one only when part of the instance answers at an address the derivation does not produce. All are optional.

The API and worker validate endpoint URLs at startup. The Gateway endpoint requires `ws://` or `wss://`. The others require `http://` or `https://`. Path prefixes and explicit ports are allowed. Credentials, fragments, whitespace, and backslashes are rejected. HTTP endpoint bases cannot contain a query. The Gateway URL may retain query parameters.

#### `NEXUS_STATIC_CDN_DOMAIN`

Default empty. A separate host for static assets. When set, the static endpoint of `api` and `worker` is forced to `https` with no port. Only `api` and `worker` read it. Set `NEXUS_STATIC_CDN_ENDPOINT` to the same origin as well for `admin`, `app-proxy` and `gateway`.

#### `NEXUS_INVITE_DOMAIN`

Default empty. The host used in invite links. A hostname with no scheme and no path.

#### `NEXUS_GIFT_DOMAIN`

Default empty. The host used in gift links. A hostname with no scheme and no path.

#### `NEXUS_API_ENDPOINT`

Defaults to the derived endpoint. The public API base. Compose forwards it from `.env` to the services on the shared block, which leaves out `app-proxy`. The `admin` service reads the same name as its internal API target, so Compose sets it to `http://api:8080` for that container.

#### `NEXUS_API_CLIENT_ENDPOINT`

Defaults to the derived endpoint. The API base handed to clients. Setting only one of the API endpoints splits what clients see from what the instance advertises.

#### `NEXUS_APP_ENDPOINT`

Defaults to the derived endpoint. The web app origin. Also one of the allowed CORS origins. Serving the client from another hostname requires setting this. Compose forwards it from `.env`, and builds it from the public origin when it is unset.

#### `NEXUS_APP_ORIGIN_ALIASES`

Default empty. Further web app origins, comma separated. Each entry must be an HTTP or HTTPS origin, or the API refuses to start. The API treats each one like the `NEXUS_APP_ENDPOINT` origin. It allows it through CORS, reads invite links on its host, skips unfurling client routes on its host, and refuses webhook token calls from it. Set it when one instance serves the web app on more than one hostname.

#### `NEXUS_GATEWAY_ENDPOINT`

Defaults to the derived endpoint. The public Gateway WebSocket URL.

#### `NEXUS_MEDIA_ENDPOINT`

Defaults to the derived endpoint. The public Media Proxy URL. The `gifs` service accepts it as a fallback for `NEXUS_MEDIA_PROXY_PUBLIC_ENDPOINT`. Compose forwards it from `.env`, and builds it from the public origin and `/media` when it is unset.

#### `NEXUS_STATIC_CDN_ENDPOINT`

Defaults to the derived endpoint. The static asset origin. Read by `api`, `worker`, `admin`, and `app-proxy`. When it is unset, `admin` gets the public origin, and every other service derives it itself.

#### `NEXUS_ADMIN_ENDPOINT`

Defaults to the derived endpoint. The admin origin. The API accepts exactly this value plus `/oauth2_callback` as the admin OAuth redirect URI. Compose forwards it from `.env`, and builds it from the public origin and `NEXUS_ADMIN_BASE_PATH` when it is unset.

The admin dashboard sets its cookie flags from the scheme of this value. Over HTTPS its CSRF cookie is named `__Host-csrf_token` and has `Secure`. Over HTTP it is named `csrf_token` without `Secure`.

#### `NEXUS_DOCS_ENDPOINT`

Defaults to an origin built from `NEXUS_PUBLIC_SCHEME`, `NEXUS_BASE_DOMAIN` and `NEXUS_PUBLIC_PORT`. The docs origin. Read by the docs server only, which the stack does not run, so Compose does not forward it.

#### `NEXUS_MARKETING_ENDPOINT`

Defaults to the derived endpoint. The marketing origin. The second allowed CORS origin. Its hostname is extracted and matched. Compose forwards it from `.env`, and uses the public origin with no path when it is unset.

#### `NEXUS_INVITE_ENDPOINT`

Defaults to the derived endpoint. The invite base. The API reads links on its hostname as invite links and does not unfurl them.

#### `NEXUS_GIFT_ENDPOINT`

Defaults to the derived endpoint. The gift base. The API does not unfurl links on its hostname.

Internal endpoints address one container from another and never appear in a browser. `NEXUS_MEDIA_PROXY_PUBLIC_ENDPOINT` is required by `gifs`. The rest are optional.

#### `NEXUS_INTERNAL_API_ENDPOINT`

Default `http://127.0.0.1:8080` in the Gateway. The API address used by `gateway` and `push`. `push` refuses to start without it. Compose sets `http://api:8080`.

#### `NEXUS_INTERNAL_MEDIA_PROXY_ENDPOINT`

Default `http://127.0.0.1:8082`. The internal Media Proxy address for `api` and `worker`. `NEXUS_MEDIA_PROXY_ENDPOINT` is read as an alias when this name is unset or empty. Compose sets `http://media-proxy:8080`.

#### `NEXUS_MEDIA_PROXY_ENDPOINT`

No default. The internal Media Proxy address. `unfurl-shard` reads this name alone and exits without it. On `api` and `worker` it is an alias of `NEXUS_INTERNAL_MEDIA_PROXY_ENDPOINT`, read only when that name is unset or empty. Compose sets `http://media-proxy:8080` on `unfurl-shard` only.

#### `NEXUS_MEDIA_PROXY_PUBLIC_ENDPOINT`

No default. The public Media Proxy URL used by `gifs`, `unfurl`, and `media-proxy`. `gifs` requires this or `NEXUS_MEDIA_ENDPOINT` to start. Set it on `media-proxy` so requests for its own assets use local storage instead of an HTTP round trip. For `api` and `worker`, use `NEXUS_MEDIA_ENDPOINT` instead. Compose forwards it from `.env` to every app service. When it is unset, they get `NEXUS_MEDIA_ENDPOINT`, or the public media URL when that is unset too.

## The edge

The `edge` container is the only HTTP entry point. Neither layout below needs a change to the edge settings.

Bundled TLS is the default. `docker compose up -d` binds `80/tcp`, `443/tcp`, and `443/udp` and obtains its own certificate for `NEXUS_DOMAIN`. Point DNS at the host and set nothing else. The `443` publishes stay on `443` whatever `NEXUS_PUBLIC_PORT` says, and `NEXUS_HTTPS_PORT` moves them.

To put your own reverse proxy in front, add the `docker-compose.proxy.yml` overlay. The edge then serves plain HTTP on one port, and the proxy in front terminates TLS. [Behind your own reverse proxy](/operator/reverse-proxy/) has the steps, the requirements, and the per-proxy configuration.

All are optional.

#### `NEXUS_EDGE_SITE_ADDRESS`

Defaults to the address Compose builds from `NEXUS_PUBLIC_SCHEME` and `NEXUS_DOMAIN` with no port. The edge's listen address. With the default, it binds `443` or `80` in the container, and `NEXUS_HTTPS_PORT` or `NEXUS_HTTP_PORT` maps it on the host. Honoured in the bundled layout only. `docker-compose.proxy.yml` sets the literal `:8080` and `tunnel.compose.yml` the literal `:80`, and either discards any `.env` value. A site address that lists more than one hostname therefore needs the bundled layout. Write the scheme into any value you set here. A bare hostname means automatic HTTPS on `443` whatever `NEXUS_PUBLIC_SCHEME` says.

#### `NEXUS_EDGE_TRUSTED_PROXIES`

Default `private_ranges`. The peer addresses whose `X-Forwarded-For` header the edge trusts. [Trusted proxies](/operator/reverse-proxy/#trusted-proxies) lists the ranges and says when to change it.

#### `NEXUS_EDGE_ENCODE`

Default `zstd gzip`. The response compression the edge offers, written as the arguments of the Caddy `encode` directive. `gzip` alone stops the edge offering zstd. Read by the edge container only, and it takes effect on `docker compose up -d edge`.

#### `NEXUS_EDGE_GLOBAL_OPTIONS`

No default. Extra Caddy global options on one line, added to the global block of the edge Caddyfile, such as `email admin@chat.example.com` for the ACME account. Compose forwards it from `.env` to `edge`, and an empty value adds nothing.

#### `NEXUS_EDGE_BIND`

Default `127.0.0.1:8080`. Where the plain-HTTP port binds. Read only under the overlay. `0.0.0.0:8080` must be firewalled to the proxy host, because the edge takes the client address from the `X-Forwarded-For` header of any peer in `NEXUS_EDGE_TRUSTED_PROXIES`.

#### `NEXUS_HTTP_PORT`

Default `80`. The host side of the edge's HTTP publish, which serves the redirect to HTTPS and the ACME HTTP challenge under an `https` scheme and nothing at all under an `http` one. The container still listens on `80` inside. It takes an optional bind address in front of the port, so `127.0.0.1:80` keeps the publish off every public interface. Do not set it to the same host port as `NEXUS_HTTPS_PORT`, because that publishes one host port twice and the edge refuses to start. `docker-compose.proxy.yml` ignores it and publishes `NEXUS_EDGE_BIND` instead. `tunnel.compose.yml` reads it with a default of `127.0.0.1:80`.

#### `NEXUS_HTTPS_PORT`

Default `443`. The host side of the edge's HTTPS publish, and the only thing it moves is that host side. Set it when the host already has something on the port the instance advertises. It moves the TCP and the UDP publish together, because HTTP/3 needs both on the same port. It takes the same optional bind address in front of the port. The overlay does not read it.

#### `COMPOSE_FILE`

No default. Which Compose files are loaded. Read by Docker Compose itself. Set it to select the overlay for every command.

`NEXUS_CADDY_SITE_ADDRESS` is the old name for `NEXUS_EDGE_SITE_ADDRESS`. Compose reads it only when `NEXUS_EDGE_SITE_ADDRESS` is unset, so an older `.env` keeps the listener it already had. Rename `NEXUS_CADDY_SITE_ADDRESS` to `NEXUS_EDGE_SITE_ADDRESS` at any time.

## Client IP

[Trusted proxies](/operator/reverse-proxy/#trusted-proxies) explains how the edge picks the client address.

All are optional.

#### `NEXUS_TRUST_CLIENT_IP_HEADER`

Default `false`. Whether the client-IP header is trusted. Compose forwards it from `.env` with a default of `true`, because the edge sets the header on every upstream hop. With `false`, `api` ignores the header and uses the address of the peer that opened the connection. That suits an `api` that clients reach directly. Behind any proxy it makes every request look as though it came from the proxy.

#### `NEXUS_CLIENT_IP_HEADER_NAME`

Default `x-forwarded-for`. Which header has the client IP. Read by `api`, `worker`, `admin`, and `gateway`. It must match what the edge sets.

#### `NEXUS_API_IP_BAN_EXEMPT_IPS`

Default empty. Addresses and CIDR ranges exempt from IP bans. Comma separated. A bare IPv4 address exempts that address, a bare IPv6 address exempts its /64, and a CIDR range such as `2001:db8:1200::/56` exempts every address in it. Every entry must parse as an IP or a CIDR range or the API fails at boot.

While `NEXUS_TRUST_CLIENT_IP_HEADER` is `true`, the API returns 403 for any request whose client-IP header is missing, empty, or not a parsable address. The exceptions are `/_health`, `/webhooks/livekit`, `/test`, and the Bluesky client metadata and JWKS routes. The edge sets the header on every upstream hop, so a missing or unparsable header happens only in a layout that puts something other than the edge directly in front of `api`. A proxy in front of the edge that never sets the header passes the check, and every request then looks as though it came from the proxy.

#### `NEXUS_API_TRUSTED_CALLERS`

Default `[]`, which keys every rate limit on the caller. A JSON array of trusted callers, such as a front end that talks to the API for its own visitors. Each entry is an object with a `name`, a `key` of at least 32 characters, and `buckets`, the rate limit buckets the caller may set the client address for. Only `donation:request_link`, `donation:manage`, `donation:checkout`, `oauth:token` and `oauth:revoke` accept it. Any other bucket name is ignored. A malformed entry or a short key fails the API at boot.

The caller sends its key in `X-NEXUS-Internal-Key` and its own client's address in `X-NEXUS-Client-Ip`. The API keys the request on that address only when the key matches an entry that lists the route's bucket. Otherwise it ignores both headers and keys the request on the caller. Self-hosters leave this empty.

```json
[{"name": "bugs", "key": "<at least 32 characters>", "buckets": ["oauth:token", "oauth:revoke"]}]
```

#### `NEXUS_API_DONATION_PROXY_KEY`

Default empty. The older form of a trusted caller limited to the three donation buckets, for the marketing site. The key must be at least 32 characters or the API fails at boot. The API also accepts the address in the older `X-NEXUS-Donor-Ip` header. Self-hosters leave this empty.

## Images

These pick which container images Compose pulls. All are optional. The image build workflows publish to the GitHub repository owner, and GitHub creates newly published container packages as private by default. A private package requires an authorized `docker login ghcr.io` to pull.

| Variable | Value in `.env.example` |
| --- | --- |
| NEXUS_REGISTRY_OWNER | `hasoon7` |
| NEXUS_REGISTRY | `ghcr.io/${NEXUS_REGISTRY_OWNER}` |
| NEXUS_IMAGE_TAG | `v1` |

`NEXUS_REGISTRY_OWNER` is the owner segment of the image names, `NEXUS_REGISTRY` the registry they are pulled from, and `NEXUS_IMAGE_TAG` the tag on every NEXUS image. Each falls back to the value in the table.

These affect only the NEXUS images. Each bundled third-party service has an image name of its own, which replaces the whole reference, registry and tag included. Set one to pull from a mirror or to move a service to another tag. All are optional.

- `NEXUS_CADDY_IMAGE`: default `caddy:2.11-alpine`, for `edge`.
- `NEXUS_POSTGRES_IMAGE`: default `postgres:16-alpine`, for `postgres`.
- `NEXUS_VALKEY_IMAGE`: default `valkey/valkey:9.1-alpine`, for `valkey`.
- `NEXUS_NATS_IMAGE`: default `nats:2.14-alpine`, for `nats`.
- `NEXUS_MEILISEARCH_IMAGE`: default `getmeili/meilisearch:v1.53`, for `meilisearch`.
- `NEXUS_SEAWEEDFS_IMAGE`: default `chrislusf/seaweedfs:4.47`, for `seaweedfs` and `seaweedfs-init`.
- `NEXUS_LIVEKIT_IMAGE`: default `livekit/livekit-server:v1.12.0`, for `livekit`.

## Database

`NEXUS_POSTGRES_HOST`, `NEXUS_POSTGRES_DATABASE`, `NEXUS_POSTGRES_USERNAME`, and `NEXUS_POSTGRES_PASSWORD` are required in production. The rest are optional.

#### `NEXUS_DATABASE_BACKEND`

Default `postgres`. Which backend is used. Node accepts only `postgres` or `cassandra`. The internal services also accept `postgresql`, `pg`, `scylla`, and `scylladb`. Every service rejects any other value at startup. Compose sets `postgres`.

#### `NEXUS_POSTGRES_URL`

Default empty. A full connection URL. When set, the discrete host, database, user, and password production checks are skipped.

#### `NEXUS_POSTGRES_HOST`

Default `127.0.0.1`. The database host. In production with `postgres` and no URL it must not be `127.0.0.1` or `localhost`. Compose forwards it from `.env` with a default of `postgres`, the bundled service.

#### `NEXUS_POSTGRES_PORT`

Default `5432`. The database port. Integer 1 to 65535.

#### `NEXUS_POSTGRES_DATABASE`

Default `nexus`. The database name. Must be non-empty. Compose forwards it from `.env`, and passes the same value to the bundled `postgres` as `POSTGRES_DB`. The Postgres image creates that database only on its first start with an empty data directory. Set it before the first start.

#### `NEXUS_POSTGRES_USERNAME`

Default `nexus`. The role. Must be non-empty. Compose forwards it from `.env`, and passes the same value to the bundled `postgres` as `POSTGRES_USER`, under the same first-start rule.

#### `NEXUS_POSTGRES_PASSWORD`

Default `nexus`. The password. The literal `nexus` is rejected in production. `CHANGE_ME` is not. Compose fills it from `POSTGRES_PASSWORD`.

#### `NEXUS_POSTGRES_SSL`

Default `false`. TLS to the database. Must be `true` or `false`. When `false`, an `sslmode` other than `prefer` in `NEXUS_POSTGRES_URL` still applies. In production it must be `true` unless `NEXUS_SELF_HOSTED=true`.

#### `NEXUS_POSTGRES_SSL_CA`

Default empty. A CA certificate in PEM form. Used only when SSL is on.

#### `NEXUS_POSTGRES_MAX_CONNECTIONS`

Default `20`. Pool size. Integer 1 to 1000, per process. The total is the sum across every container. Only `api`, `worker`, `users-shard` and `messages-shard` open a pool, and Compose sets it in each from the per-service name below.

#### `NEXUS_API_POSTGRES_MAX_CONNECTIONS`

Default `25`. The pool size of `api`. Read by Compose, which passes it to `api` as `NEXUS_POSTGRES_MAX_CONNECTIONS`.

#### `NEXUS_WORKER_POSTGRES_MAX_CONNECTIONS`

Default `25`. The pool size of `worker`, passed the same way.

#### `NEXUS_USERS_SHARD_POSTGRES_MAX_CONNECTIONS`

Default `20`. The pool size of `users-shard`, passed the same way.

#### `NEXUS_MESSAGES_SHARD_POSTGRES_MAX_CONNECTIONS`

Default `20`. The pool size of `messages-shard`, passed the same way.

#### `NEXUS_POSTGRES_KV_TABLE`

Default `nexus_kv`. The key-value table name. Must match a safe Postgres identifier or startup fails.

#### `NEXUS_POSTGRES_PREPARED_STATEMENTS`

Default `true`. Named prepared statements. Must be `true` or `false`. Compose forwards it in the shared block, so one value governs `api`, `worker` and the Rust services at once. Set it to `false` behind a transaction-pooling pooler such as PgBouncer, where a named statement outlives the session that declared it.

Cassandra or Scylla is an alternative backend, selected with `NEXUS_DATABASE_BACKEND=cassandra`. Supply a reachable database and configure the settings below when selecting it. The bundled stack uses Postgres, does not include a Cassandra or Scylla service, and forwards none of the names below.

#### `NEXUS_CASSANDRA_HOSTS`

Default `127.0.0.1`. Contact points. Comma separated. The Rust services normalise each entry to host and port, with IPv6 bracketed.

#### `NEXUS_CASSANDRA_PORT`

Default `9042`. The port. Integer.

#### `NEXUS_CASSANDRA_KEYSPACE`

Default `nexus`. The keyspace. Must exist already.

#### `NEXUS_CASSANDRA_LOCAL_DC`

Default `datacenter1`. The local datacentre. Read by `api` and `worker` only. The Rust services ignore it.

#### `NEXUS_CASSANDRA_USERNAME`

Default empty. The login. Empty means no authentication.

#### `NEXUS_CASSANDRA_PASSWORD`

Default empty. The password. Empty means no authentication.

## Object storage

Every uploaded file lands in an S3-compatible object store, which the stack provides with SeaweedFS. `NEXUS_S3_ACCESS_KEY_ID` and `NEXUS_S3_SECRET_ACCESS_KEY` are required. The rest are optional. [Run a data store outside the stack](/operator/upgrading/#run-a-data-store-outside-the-stack) has the overlay that stops the bundled SeaweedFS once the stack points at another store.

#### `NEXUS_S3_ENDPOINT`

Default `http://localhost:3900`. The S3 API address. `media-proxy` defaults to empty instead. Compose forwards it from `.env` with a default of `http://seaweedfs:8333`, the bundled store.

An endpoint with a bucket in its path, such as `https://s3.example.com/my-bucket` with `NEXUS_S3_FORCE_PATH_STYLE=true`, keeps every NEXUS bucket inside that one bucket. Each bucket name becomes a key prefix there, so uploads land under `nexus-uploads/` in `my-bucket`.

An endpoint with the bucket in its hostname, such as `https://my-bucket.s3.example.com` with `NEXUS_S3_FORCE_PATH_STYLE=true`, turns each bucket name into a key prefix the same way. The store cannot resolve a NEXUS bucket name as the source of a server-side copy there. The API downloads the object to its temporary directory and uploads the copy from there.

The API cannot list objects through either kind of endpoint, because the store reads the bucket name in a listing request as a key. [Report deletion](/admin-api/reports/#report-retention) lists a report's profile snapshot images first. On a store that answers the listing with an error, the deletion fails. Separate buckets do not have this limit.

#### `NEXUS_S3_PUBLIC_ENDPOINT`

No default. The host substituted into presigned URLs, which are the only place it appears. Compose forwards it from `.env`, and uses `NEXUS_S3_ENDPOINT` when it is unset, except on `app-proxy`, which gets only a value `.env` sets and adds it to its Content Security Policy. `admin` reads it to find the origin that report downloads are presigned against. See `NEXUS_S3_BUCKET_REPORTS`.

#### `NEXUS_S3_FORCE_PATH_STYLE`

Default `false`. Path-style addressing. `media-proxy` defaults to `true` instead. Compose forwards it from `.env` with a default of `true`, which the bundled store needs.

#### `NEXUS_S3_REGION`

Default `local`. The region string. `media-proxy` defaults to `us-east-1`. Compose forwards it from `.env` with a default of `us-east-1`, so every service signs for the same region.

#### `NEXUS_S3_ACCESS_KEY_ID`

Default empty. The access key. Config validation requires it non-empty on `api` and `worker`. Optional for `media-proxy`. Compose fills it from `NEXUS_S3_ACCESS_KEY`.

#### `NEXUS_S3_SECRET_ACCESS_KEY`

Default empty. The secret key. Config validation requires it non-empty on `api` and `worker`. Optional for `media-proxy`. Compose fills it from `NEXUS_S3_SECRET_KEY`.

#### `NEXUS_S3_SESSION_TOKEN`

Default empty. A temporary session token. Read by `media-proxy` only.

#### `NEXUS_S3_BUCKET_CDN`

Default `nexus`. Processed assets. `media-proxy` defaults to `cdn`. Compose forwards it from `.env` with a default of `nexus`, so every service and `seaweedfs-init` name the same bucket.

#### `NEXUS_S3_BUCKET_UPLOADS`

Default `nexus-uploads`. Raw uploads. `media-proxy` defaults to `uploads`, `app-proxy` to `nexus-uploads`. Compose forwards it from `.env` with a default of `nexus-uploads` for the same reason.

#### `NEXUS_S3_BUCKET_REPORTS`

Default `nexus-reports`. Abuse report evidence. Read by `api`, `worker`, and `admin`. Compose forwards it from `.env` with a default of `nexus-reports`, so every service and `seaweedfs-init` name the same bucket. `admin` allows one image origin for report attachments and profile snapshots in its Content Security Policy, the origin `api` presigns report downloads against. It works that origin out from this name, `NEXUS_S3_PUBLIC_ENDPOINT` or else `NEXUS_S3_ENDPOINT`, `NEXUS_S3_FORCE_PATH_STYLE` and `NEXUS_S3_BUCKET_UPLOADS`, so give `admin` the same values as `api`. The images load only when that origin is an address browsers can reach.

#### `NEXUS_S3_BUCKET_HARVESTS`

Default `nexus-harvests`. Data archives. Read by `api` and `worker`. Compose forwards it from `.env` with a default of `nexus-harvests`, so every service and `seaweedfs-init` name the same bucket.

#### `NEXUS_S3_BUCKET_STATIC`

Default `static`. Static assets. Read by `media-proxy` only in `static` mode, which the stack does not use. `api` and `worker` never read it, and `seaweedfs-init` does not create this bucket. Compose does not forward it.

The Media Proxy read path has overrides of its own. All are optional.

#### `NEXUS_S3_READ_ENDPOINT`

Falls back to `NEXUS_S3_ENDPOINT`. The read-side S3 address. Must be http or https with a host, and have no credentials, query string, or fragment.

#### `NEXUS_S3_READ_BUCKET`

Falls back to `NEXUS_S3_BUCKET_CDN`. The read-side bucket. Read by `media-proxy` only.

#### `NEXUS_S3_READ_BUCKET_STYLE`

Defaults to `path` when path style is on, else `virtual`. How the bucket appears in the URL. `path`, `virtual`, or `root`. Anything else is a startup error.

#### `NEXUS_S3_READ_SIGNED`

Default `false`. Whether read requests are signed. Read by `media-proxy` only. Compose forwards it from `.env` with a default of `true`, because `seaweedfs-init` installs an S3 identity and the store then refuses anonymous reads. Set `false` only for a public-read bucket.

## Message bus and internal services

The bundled stack requires NATS for communication between services and JetStream for background jobs. Compose forwards the connection settings from `.env`, with the bundled service as the default. Change them when using an external NATS service, which must have JetStream enabled for the worker connection.

#### `NEXUS_NATS_URL`

Default `nats://127.0.0.1:4222`. The core NATS address for `api`, `worker`, and `gateway`. The Gateway defaults to `nats://nats:4222` instead. Compose forwards it from `.env` with a default of `nats://nats:4222`.

#### `NEXUS_NATS_CORE_URL`

Alias of `NEXUS_NATS_URL` on `api` and `worker`, read only when that name is unset or empty. The core NATS address. Not read by the Gateway. Compose does not forward it, because it forwards `NEXUS_NATS_URL`.

#### `NEXUS_NATS_JETSTREAM_URL`

Default `nats://127.0.0.1:4222`. The JetStream address for `api` and `worker`. Compose forwards it from `.env`, and uses `NEXUS_NATS_URL` when it is unset.

#### `NEXUS_NATS_AUTH_TOKEN`

Default empty. NATS authentication. Read by `api`, `worker`, `gateway`, and the internal services. The shipped NATS runs without authentication, and Compose forwards this name to every container that connects to it.

#### `NEXUS_SVC_NATS_URL`

Default `nats://127.0.0.1:4222`. The NATS address for the internal services and `push`. A separate variable from `NEXUS_NATS_URL`. Compose forwards it from `.env`, and uses `NEXUS_NATS_URL` when it is unset.

#### `NEXUS_GATEWAY_API_RPC_ENDPOINT`

No default. Where the Gateway calls the API. Read by the Gateway, which derives it from `NEXUS_INTERNAL_API_ENDPOINT` when it is unset. Compose does not forward it.

Compose configures the internal services. Change the following settings only when customising their deployment.

#### `NEXUS_SVC_NAME`

Default `default`. The metrics prefix. It also selects the built-in default of `NEXUS_SVC_MAX_CONCURRENT_REQUESTS`. Changing it does not rename NATS subjects. Compose sets it per service.

#### `NEXUS_SVC_MODE`

Default `router`. Must be `router` or `shard`. Any other value prevents startup. Compose sets it per service.

#### `NEXUS_SVC_SHARD_COUNT`

Default `1`. How many shards exist. Compose fixes it at `1`.

#### `NEXUS_SVC_SHARD_ID`

Derived from the numeric suffix of `POD_NAME`, else `0`. Which shard this process is. A shard ID at or above the shard count is a startup error. Compose sets `0` on every shard.

#### `NEXUS_SVC_LISTEN_HOST`

Default `0.0.0.0`. The bind address. Serves health and metrics only. Compose does not forward it.

#### `NEXUS_SVC_PORT`

Default `8090`. The health and metrics port. Not published. Compose does not forward it, because every internal service health check probes `8090`.

#### `NEXUS_SVC_MAX_CONCURRENT_REQUESTS`

Defaults to 192 for messages, 320 for snowflakes, 64 otherwise. In-flight request ceiling. The built-in defaults key off `NEXUS_SVC_NAME`. Compose forwards it from `.env` to every internal service router and shard. Left unset, each keeps its built-in default. Once set, the one value replaces the default on all of them, so a value below 320 also lowers the snowflakes ceiling. A router holds a slot for the whole round trip to its shard. A request over the ceiling is rejected at once. The API request behind it fails with a 503, and the API logs `shard rejected the request because it is at its concurrency limit`.

#### `POD_NAME`

No default. The shard ordinal source and node identity. Also read by the Gateway, and by the API as the `pod_name` in its RPC timing records. Compose does not set it.

The API reaches the internal services over NATS. Compose forwards the client names and the tuning values below from `.env`. It does not forward `NEXUS_SNOWFLAKE_SERVICE_SUBJECT`, `NEXUS_USERS_SERVICE_SUBJECT` or `NEXUS_GIF_SERVICE_SUBJECT`, because each has to match the subject its internal service listens on.

Numeric settings require decimal safe integers. Surrounding whitespace is trimmed, and omitted or blank settings use the defaults. Explicit malformed or out-of-range values are rejected.

- `NEXUS_SNOWFLAKE_SERVICE_NATS_CLIENT_NAME`, `NEXUS_USERS_SERVICE_NATS_CLIENT_NAME` and `NEXUS_GIF_SERVICE_NATS_CLIENT_NAME`: the name the API gives each NATS connection, as NATS monitoring shows it. Each defaults to a name for its service.
- `NEXUS_SNOWFLAKE_SERVICE_BATCH_SIZE`: defaults to `128`. Accepts 1 to 512.
- `NEXUS_SNOWFLAKE_SERVICE_LOW_WATERMARK`: defaults to `32`, capped below the batch size. Accepts 0 through batch size minus one.
- `NEXUS_SNOWFLAKE_SERVICE_MAX_BUFFER_AGE_MS`: defaults to `5000`. Accepts 1 to 60000 milliseconds.
- `NEXUS_SNOWFLAKE_SERVICE_REQUEST_TIMEOUT_MS`: defaults to `6000`. Accepts 1 to 60000 milliseconds.
- `NEXUS_USERS_SERVICE_TIMEOUT_MS`: defaults to `6000`. Accepts 1 to 2147483647 milliseconds.
- `NEXUS_USERS_SERVICE_INFLIGHT_MAX_ENTRIES`: defaults to `10000`. Accepts 0 through the largest safe integer.
- `NEXUS_GIF_SERVICE_TIMEOUT_MS`: defaults to `12000`. Accepts 1 to 2147483647 milliseconds.
- `NEXUS_GIF_SERVICE_REGISTER_SHARE_TIMEOUT_MS`: defaults to `3000`. Accepts 1 to 2147483647 milliseconds.

A Snowflake low watermark of `0` disables background refill before the buffer is empty. A Users in-flight entry limit of `0` disables request coalescing. It is not a limit on concurrent requests.

## Voice and LiveKit

LiveKit is the media server for voice and video. `NEXUS_LIVEKIT_API_KEY` and `NEXUS_LIVEKIT_API_SECRET` are required for voice. The rest are optional.

#### `NEXUS_LIVEKIT_ENABLED`

Default `false`. The master switch for all voice and video. Compose forwards it from `.env` with a default of `true`, because the stack ships LiveKit.

#### `NEXUS_LIVEKIT_API_KEY`

Default empty. The LiveKit API key. Compose fills it from `LIVEKIT_API_KEY`.

#### `NEXUS_LIVEKIT_API_SECRET`

Default empty. The LiveKit secret. Compose fills it from `LIVEKIT_API_SECRET`.

#### `NEXUS_LIVEKIT_URL`

Default empty. The client-facing LiveKit URL. Set it only when LiveKit is served from another host. `docker-compose.yml` never passes it empty: it builds the value from `NEXUS_PUBLIC_ORIGIN`, or from `NEXUS_PUBLIC_SCHEME`, `NEXUS_DOMAIN` and `NEXUS_PUBLIC_PORT` when the origin is unset, followed by `/livekit`, and forwards a value `.env` sets. An empty value outside Compose has the API derive `wss://host/livekit` from the public API origin, or `ws://` under `http`, with a non-default port kept.

#### `NEXUS_LIVEKIT_USE_EXTERNAL_IP`

Default `true`. Whether LiveKit discovers the address browsers dial by asking a STUN server. A host that cannot reach one over UDP fails to start with `could not resolve external IP: context deadline exceeded`. Set it to `false` and give `NEXUS_LIVEKIT_NODE_IP` the address instead. Read only by the `livekit` service.

#### `NEXUS_LIVEKIT_NODE_IP`

Default empty. The address LiveKit publishes in its ICE candidates. Empty leaves the choice to the discovery above, and with that discovery off LiveKit falls back to the container's own address, which no browser can reach. Set both together. `docker compose logs livekit` names the address in use as `nodeIP` on the starting line.

#### `NEXUS_LIVEKIT_STUN_PRIMARY`

Default `stun.l.google.com:19302`. The first STUN server the discovery asks. Point it at another server to keep the discovery without reaching Google.

#### `NEXUS_LIVEKIT_STUN_SECONDARY`

Default `stun1.l.google.com:19302`. The second STUN server, used the same way.

#### `NEXUS_LIVEKIT_INTERNAL_URL`

Default empty. The server-side LiveKit control API. Compose forwards it from `.env` with a default of `http://livekit:7880`, the bundled service.

#### `NEXUS_LIVEKIT_DEFAULT_REGION`

No default. The default voice region. JSON with `id`, `name`, `emoji`, `latitude`, and `longitude`. Compose forwards it from `.env`, with a default region named `Default` at latitude and longitude `0`.

#### `NEXUS_LIVEKIT_LOG_LEVEL`

Default `info`. How much LiveKit logs. Read by Compose only, which writes it into the LiveKit configuration as `log_level`.

#### `NEXUS_LIVEKIT_TCP_PORT`

Default `7881`. The TCP media port. Read by Compose only. Compose publishes it on the host and passes it to LiveKit as `rtc.tcp_port`, so the port LiveKit advertises in ICE candidates is the one the host forwards.

#### `NEXUS_LIVEKIT_UDP_PORT`

Default `7882`. The UDP media port, published and passed to LiveKit as `rtc.udp_port` the same way.

Compose points LiveKit at the webhook target `http://api:8080/webhooks/livekit` and configures no TURN server. The API accepts requests on that route without user authentication and without a client-IP header. A client that cannot use UDP falls back to ICE-TCP on the TCP port.

Moving a media port is one line in `.env` followed by `docker compose up -d livekit`. Compose puts the same value on the host side of the mapping, on the container side, and on the `rtc` port LiveKit advertises in the ICE candidates it hands to clients.

To rotate the key pair, set both names in `.env`, then run `docker compose up -d livekit api worker` to apply the change everywhere.

### Peer-to-peer calls

A peer-to-peer call sends media directly between its participants and not through LiveKit or any relay. It runs only while the `voice_p2p` experiment is enabled in the [instance configuration](/admin-api/instance/). The value below names the STUN servers NEXUS hands to each participant. It is optional. The stack ships no STUN server.

#### `NEXUS_VOICE_P2P_STUN_URLS`

Default empty. A comma-separated list of `stun:` URLs. Participants use them to discover their public addresses.

Unset, participants receive no ICE servers and connect only when they can already reach each other, as on one local network. Two participants that cannot reach each other directly fail to connect, and either one can switch the call to LiveKit. Participants in a peer-to-peer call can learn each other's IP addresses.

## Email

Only an instance where members sign in with email sends mail. A username instance sends none whatever the values below hold, and needs none of them. [Sign-in methods](/operator/sign-in/) covers the difference.

Email is off by default. It works only when the email switch is on and the provider is `smtp` with `NEXUS_EMAIL_FROM_EMAIL`, `NEXUS_EMAIL_SMTP_HOST`, `NEXUS_EMAIL_SMTP_PORT`, `NEXUS_EMAIL_SMTP_USERNAME` and `NEXUS_EMAIL_SMTP_PASSWORD` all non-empty. The switch is the value saved in the admin dashboard, or `NEXUS_EMAIL_ENABLED` when the dashboard has no saved value. An SMTP value saved in the admin dashboard also wins over the matching variable. All are optional.

The Replit preview is an exception: its launcher disables the local Mailpit sink unless a complete SMTP configuration is supplied through Replit environment variables. When supplied, those environment values take precedence over older email settings stored in the instance database. This prevents the preview from reporting success for a message captured only by a local test inbox.

For a personal Gmail account, use `smtp.gmail.com`, port `587`, and TLS mode `starttls`. Set the sender address and SMTP username to the same Gmail address, and use a Google App Password as `NEXUS_EMAIL_SMTP_PASSWORD` (not the normal Google account password). Google requires 2-Step Verification for App Passwords: [Google App Password instructions](https://support.google.com/accounts/answer/185833) and [create an App Password](https://myaccount.google.com/apppasswords). Personal Gmail has sending limits and is not a transactional-mail delivery guarantee; Google Workspace is a paid service with plan and region-dependent pricing. For a custom sender domain, configure its SPF/DKIM records in Google Workspace: [Google DKIM setup](https://support.google.com/a/answer/174124).

While email is on, registration checks the address domain. It has to publish an `MX` record, or an `A` or `AAAA` record as a fallback. An address at a domain that publishes neither is answered `That email domain cannot receive mail.` however well formed it is. The first admin account is no exception. An owner address at a `.lan`, `.internal` or `home.arpa` name needs email left off.

#### `NEXUS_EMAIL_ENABLED`

`.env.example` `false`. The delivery switch. The admin dashboard value wins over this.

#### `NEXUS_EMAIL_PROVIDER`

`.env.example` `none`. The transport. `smtp` or `none`. Anything else fails startup.

#### `NEXUS_EMAIL_FROM_EMAIL`

`.env.example` `noreply@example.com`. The sender address. Default empty. Compose forwards it from `.env`, and uses `noreply@localhost` when it is unset.

#### `NEXUS_EMAIL_FROM_NAME`

`.env.example` empty. The sender name. Default empty. An empty value sends mail under the instance product name, which is the name saved in the admin dashboard or else `NEXUS_APP_PRODUCT_NAME`, and a rename in the dashboard applies to the next email. A set value always wins.

#### `NEXUS_EMAIL_REPLY_TO_EMAIL`

Default empty. The address replies go to, sent as the `Reply-To` header on every email. An empty value sends no `Reply-To` header. Must be a single bare address such as `support@example.com`, or the API fails at boot. The admin dashboard has no field for it. `.env.example` lists it commented out.

#### `NEXUS_EMAIL_APP_BASE_URL`

`.env.example` empty. The base URL used in links. Must be http or https with no username, password, query, or fragment, or the API fails at boot. Falls back to the app endpoint.

#### `NEXUS_EMAIL_SMTP_HOST`

`.env.example` empty. The SMTP host. Setting any SMTP variable creates the whole SMTP block, which is absent by default.

#### `NEXUS_EMAIL_SMTP_PORT`

`.env.example` `587`. The SMTP port. Falls back to 587.

#### `NEXUS_EMAIL_SMTP_USERNAME`

`.env.example` empty. The SMTP login. Part of the completeness check.

#### `NEXUS_EMAIL_SMTP_PASSWORD`

`.env.example` empty. The SMTP password. Part of the completeness check.

#### `NEXUS_EMAIL_SMTP_TLS_MODE`

`.env.example` empty. How the SMTP connection is encrypted. Anything other than the four values below fails startup.

| Value | Connection |
| ----- | ---------- |
| `implicit` | TLS from the first byte. Most providers serve this on port 465 |
| `starttls` | A plain connection that must upgrade with STARTTLS before the login. Most providers serve this on port 587 |
| `opportunistic` | A plain connection that upgrades with STARTTLS when the server offers it, and stays plain when it does not |
| `none` | No TLS, even when the server offers STARTTLS. Only for a mail server on a network you trust |

An empty value picks the mode from the port: `implicit` on port 465 and `starttls` on every other port. A mode saved in the admin dashboard wins over this variable, and choosing Automatic there hands the choice back to it. The dashboard shows the mode outgoing email ends up with. Automatic in the setup wizard saves the mode the port calls for, so it never follows this variable or `NEXUS_EMAIL_SMTP_SECURE`.

#### `NEXUS_EMAIL_SMTP_SECURE`

`.env.example` unset. The older switch, read only while `NEXUS_EMAIL_SMTP_TLS_MODE` is empty. `true` means `implicit` and `false` means `opportunistic`. `.env.example` lists it commented out. An older `.env` can hold `NEXUS_EMAIL_SMTP_SECURE=true` next to port 587, and that pair fails against a STARTTLS server with `wrong version number`. Remove the line or set `NEXUS_EMAIL_SMTP_TLS_MODE`.

The Save and test button in the admin dashboard, and [Create SMTP test](/admin-api/instance/#create-smtp-test) with an empty body, connect with the saved settings, the same ones outgoing email uses, and fail with the reason when outgoing email is turned off or incomplete. A send that fails is logged by `api` or `worker` as `SMTP send failed` with the host, port and TLS mode.

The API reads `NEXUS_EMAIL_WEBHOOK_SECRET` for inbound delivery webhooks. `.env.example` lists it commented out.

The API registers `POST /webhooks/sweego` on every deployment. The route authenticates the Standard Webhooks header triple `webhook-id`, `webhook-timestamp`, and `webhook-signature` against that secret, and answers 404 `Email not enabled` while email is off. The route sits outside the client-IP exempt list that covers `/webhooks/livekit`, so give the provider a delivery URL that goes through the edge, `https://chat.example.com/api/webhooks/sweego`.

Only `api` and `worker` build the mail service, so recreating those two is enough after a change.

## Single sign-on and passkeys

All are optional.

Default `false`. Whether the SSO provider URL may resolve to a private address. Off by default as SSRF protection. Turn it on only for split-horizon DNS or a LAN identity provider.

#### `NEXUS_PASSKEY_RP_ID`

Defaults to the host of `NEXUS_PUBLIC_ORIGIN` when that is set, and to `NEXUS_BASE_DOMAIN` otherwise. The WebAuthn relying party identifier. Compose forwards it from `.env` with a default of `NEXUS_DOMAIN`. With that default, moving the public origin to another host leaves existing passkeys valid.

#### `NEXUS_PASSKEY_RP_NAME`

Default `NEXUS`. The relying party name browsers display. Does not follow `NEXUS_DOMAIN`.

#### `NEXUS_PASSKEY_ADDITIONAL_ALLOWED_ORIGINS`

The complete accepted origin set, comma separated. Despite the name, an explicit value replaces the defaults and must list every origin clients use. Compose forwards it from `.env` with a default of the public web app origin, so a self-hosted instance accepts its own origin alone. When the variable is omitted or empty outside Compose, the API accepts the configured app origin alongside the built-in NEXUS web and Android origins. To accept only the app origin, list it alone.

Each web entry must be an HTTP(S) origin with no credentials, path beyond an optional final slash, query, or fragment. Web origins are normalised to browser form using the configured public port unless the entry supplies one. Android entries must use `android:apk-key-hash:` followed by the signing certificate's SHA-256 fingerprint in canonical, unpadded base64url (43 characters). A passkey is bound to the `NEXUS_PASSKEY_RP_ID` it was registered under. Members have to enrol again after a change, so pick the value before opening registration.
:::

## Payments

Stripe billing for a paid premium tier and gift purchases. All are optional. On a self-hosted instance, set billing in the admin dashboard's [Premium & billing](#runtime-settings-in-the-admin-dashboard) group instead. A value stored there wins over the matching variable below.

A self-hosted instance sells premium only while its premium mode is `mirror`, billing is switched on, a Stripe secret key is set, and at least one currency has both a monthly and a yearly price. Instance discovery reports this as `stripe_enabled`. Existing subscribers can still manage, cancel and renew while the premium mode is `mirror` and a Stripe secret key is set, even after sales are switched off or the prices are removed. Instance discovery reports this as `stripe_serviceable`. Stripe sends events to `https://<NEXUS_DOMAIN>/api/stripe/webhook`, which the dashboard shows as the webhook URL to register in Stripe.

#### `NEXUS_STRIPE_ENABLED`

Default `false`. The Stripe switch.

#### `NEXUS_STRIPE_SECRET_KEY`

Default empty. The Stripe secret key.

#### `NEXUS_STRIPE_WEBHOOK_SECRET`

Default empty. The webhook signing secret.

#### `NEXUS_STRIPE_PRICES`

Default `{}`. Every price ID at once. JSON object.

Individual price variables also exist, one per product and currency: `NEXUS_STRIPE_PRICE_MONTHLY_`, `NEXUS_STRIPE_PRICE_YEARLY_`, `NEXUS_STRIPE_PRICE_GIFT_1_MONTH_` and `NEXUS_STRIPE_PRICE_GIFT_1_YEAR_` in USD, EUR, BRL, DKK, INR, ISK, NOK, PLN, SEK, and TRY. Each overrides the matching price in this object. Compose does not forward them, so a self-hosted instance sets prices with this variable or in the admin dashboard.

Prices saved in the dashboard replace this catalogue entirely. They take any three-letter currency code. A buyer gets the currency mapped to their country, then the default currency, then the first configured one. NEXUS's country checks for localised currencies apply only to prices set by these variables.

A self-hosted instance never sets Stripe Adaptive Pricing on its Checkout Sessions, so the setting in the Stripe Dashboard applies. The hosted service turns it off for SEK, NOK, DKK and ISK sessions so buyers pay the native price.

#### `NEXUS_STRIPE_LEGACY_PRICES`

Default `{}`. Retired price IDs, keyed by the same slot names `NEXUS_STRIPE_PRICES` uses, each mapped to a list, such as `{"monthly_brl": ["price_..."]}`. JSON object. Existing subscriptions on these prices keep renewing. The localised checkout catalogue uses `NEXUS_STRIPE_PRICES` alone. Legacy prices saved in the dashboard replace this variable, and there the currency in a slot name is upper case, such as `monthly_GBP`.

Reprice a slot in this order. Create the new price in Stripe, move the ID it replaces into this variable, roll the API, and only then point `NEXUS_STRIPE_PRICES` at the new price. A price ID that neither variable names is unknown to the API. A renewal invoice on it fails the webhook with `Unknown product for invoice renewal`, a checkout completing on it fails with `Unknown price ID for checkout session`, and both keep failing until the ID is registered. The API answers Stripe once the signature verifies and hands the event to `worker`. Retries come from `worker` rerunning the `processStripeWebhook` job. The Stripe dashboard shows the delivery as succeeded, and the error is in the `worker` logs. Keep a retired ID listed while any subscription still bills on it. For a yearly price that is at least a year after the switch.

With prices saved in the dashboard, add the retired ID to its legacy prices before you replace the price.

## Moderation and abuse

All are optional.

#### `NEXUS_CLAMAV_ENABLED`

Default `false`. Upload virus scanning. No ClamAV container ships.

#### `NEXUS_CLAMAV_HOST`

Default `127.0.0.1`. The scanner host. Needs a reachable scanner.

#### `NEXUS_CLAMAV_PORT`

Default `3310`. The scanner port. Integer.

#### `NEXUS_CLAMAV_FAIL_OPEN`

Default `false`. Behaviour when the scanner is unreachable. With scanning on and this off, an unreachable scanner rejects every upload.

#### `NEXUS_BLOCKLIST_FEEDS_ENABLED`

Defaults to the inverse of `NEXUS_SELF_HOSTED`. Off by default on a self-hosted instance. With feeds on, the worker downloads the URLhaus and PhishTank URL lists every six hours, and MalwareBazaar file hashes every twelve hours. NEXUS checks posted links against the URLs and uploads against the hashes.

With feeds off, NEXUS checks none of this data. The first worker start with feeds off removes the URL feed file and every `malware_bazaar` file-SHA ban that no Admin added. File-SHA bans added through the Admin API stay. Turning feeds back on downloads the URLs within six hours and the hashes within twelve.

#### `NEXUS_REPORT_RETENTION_DAYS`

Default `365`. Read by `worker`. The daily [report retention](/admin-api/reports/#report-retention) job deletes each report this many days after it was filed, pending or resolved, with its evidence copies and search entry, unless a legal hold is in place. Integer 1 to 36500, checked at startup.

#### `NEXUS_RESOLVED_REPORT_RETENTION_DAYS`

Default unset, which leaves resolved reports to `NEXUS_REPORT_RETENTION_DAYS`. Read by `worker`. When set, a resolved report is deleted this many days after it was resolved, if that comes before the end of its retention period. Pending reports are not affected, and a legal hold still keeps a report. Integer 1 to 36500, checked at startup.

#### `NEXUS_REPORT_RETENTION_DRY_RUN`

Default `false`. Read by `worker`. With `true`, each run only counts what it would delete and deletes nothing. `true` or `false`, checked at startup. Deleted evidence cannot be restored. Check the counts in the `Processed report retention` log line before the first real run.

#### `NEXUS_BREACHED_PASSWORD_CHECK_ENABLED`

Defaults to the inverse of `NEXUS_SELF_HOSTED`. Breached password rejection. Sends the first five characters of the password's SHA-1 hash to `api.pwnedpasswords.com`. Off by default on a self-hosted instance.

## Stored instance policy

Use the [admin dashboard](#runtime-settings-in-the-admin-dashboard) or [Admin instance API](/admin-api/instance/) to change saved settings. Missing settings use their documented defaults. Invalid JSON, field types, identifiers or out-of-range values cause an error instead of silently resetting security or registration policy.

Invalid saved configuration prevents the API and worker from starting. If a running process cannot apply an update, it logs the error and keeps its previous valid settings. Check the reported section and field paths, repair the saved configuration, then retry. It is not repaired automatically.

The API and worker read configuration saved by older releases under these rules:

- Gateway rollout accepts `nats_request_timeout_ms` only when `rpc_request_timeout_ms` is absent. Both require an integer from 1000 to 60000. Use the current name in Admin requests.
- Registration accepts `adminRegistrationUrlsEnabled` only when `admin_registration_urls_enabled` is absent. Missing registration settings default to `open` with admin registration URLs enabled.
- Missing SSO settings default to disabled. A missing enforcement flag takes the value of the enabled flag, and automatic provisioning defaults to on. Stored flags require `true` or `false`.
- SSO allowed domains accept a JSON string array or a legacy comma-separated list of at most 100 entries. Domains are trimmed, lowercased, IDNA encoded and deduplicated. An empty list leaves domains unrestricted. Invalid lists must be repaired even while SSO is disabled.
- A self-hosted instance with no stored sign-in method gets one on its next start, by the rules in [Sign-in methods](/operator/sign-in/#instances-that-already-exist). Until that write succeeds the instance behaves as an email instance.
- Missing registration URL and pending-registration lists mean empty lists. Invalid records are rejected rather than discarded. Timestamps require an explicit UTC marker or offset, and null is accepted only for nullable fields.

Explicit `false` values and supported null clears remain valid. Branding and integration strings retain their documented trimming and blank-value behaviour. Media size and lifetime adjustments also remain unchanged. These checks do not make a multi-section update atomic. Read back the result after a failed write before retrying.

## Instance identity and branding

A product name or brand asset saved in the admin dashboard wins over its variable. All are optional.

A brand asset on another origin than the instance needs no CSP setting. `app-proxy` adds the origin of each of the five image URLs below to `img-src`, whether the URL is set here or in the dashboard. [Content Security Policy](#content-security-policy) has the timing.

`app-proxy` on a self-hosted instance also writes the product name, the icon, the favicon and the theme colour into the page it serves, so a browser shows them before the web app starts. ## API and worker settings

`NEXUS_API_WORKER_TASK` is required under `single_task`. The rest are optional.

#### `NEXUS_API_PORT`

Default `8080`. The API listen port. Compose sets `8080`, which the edge proxies to.

#### `NEXUS_API_HEADERS_TIMEOUT_MS`

Default `30000`. How long a client may take to send the request line and the headers. Integer 1000 to 3600000, checked at startup. It is clamped down to `NEXUS_API_REQUEST_TIMEOUT_MS`. Raising it alone does nothing.

#### `NEXUS_API_REQUEST_TIMEOUT_MS`

Default `120000`. How long a client may take over the whole request. Integer 1000 to 3600000, checked at startup. This is the one to raise for large uploads or high latency links.

#### `NEXUS_API_WORKER_MODE`

Default `all_lanes`. Which lanes the worker runs. `all_lanes`, `single_lane`, or `single_task`. Anything else fails startup. Compose sets `all_lanes`, because the stack runs one `worker`.

#### `NEXUS_API_WORKER_LANE`

No default. Which lane, under `single_lane`. `realtime`, `unfurl`, `lifecycle`, `batch`, or `crosspost`. Compose does not forward it. A deployment that splits the worker by lane needs a `crosspost` worker, or published announcements are never delivered.

#### `NEXUS_API_WORKER_TASK`

No default. Which task, under `single_task`. Must name a known task. Compose does not forward it.

#### `NEXUS_API_WORKER_ENABLE_CRON_SCHEDULER`

No default. Whether the cron scheduler runs. Compose sets `true`. Without it no scheduled job runs anywhere.

#### `NEXUS_API_WORKER_LANE_CONCURRENCY_OVERRIDES`

No default. Per-lane concurrency. JSON object keyed by lane, `realtime`, `unfurl`, `lifecycle`, `batch`, or `crosspost`. Each value must be an integer of at least 1 or startup fails. Built-in concurrency is realtime 10, unfurl 20, lifecycle 8, batch 12, crosspost 8.

#### `NEXUS_NODE_EXTRA_CA_CERTS`

Default `/etc/ssl/certs/ca-certificates.crt`, the system bundle in the image. A PEM file of extra CA certificates that `api` and `worker` trust for every outbound TLS connection, such as SMTP, object storage, search and webhooks. Node trusts its own built-in roots plus this one file. A file you set replaces the system bundle, so append your CA to a copy of that bundle, mount it into both containers and point this at it. Compose passes it to `api` and `worker` as `NODE_EXTRA_CA_CERTS`, and keeps the image path when `.env` leaves it out. It reads the prefixed name so a `NODE_EXTRA_CA_CERTS` in the host shell does not reach the containers.

## Media Proxy settings

The Media Proxy takes uploads, transforms images, and serves media back. All are optional.

#### `NEXUS_MEDIA_PROXY_MODE`

Default `mp`. Which routes are served. `mp`, `static`, `upload`, or `relay`. `relay` serves the upload relay and the operator and internal endpoints, and returns 404 for every read. Anything else is a startup error. Also settable with `--mode`. Compose sets `upload`, which the upload relay needs.

#### `NEXUS_MEDIA_PROXY_HOST`

Default `0.0.0.0`. The bind address. Also settable with `--bind-host`. Compose does not set it, so the default applies.

#### `NEXUS_MEDIA_PROXY_PORT`

Default `8080`. The listen port. Also settable with `--port`. Compose sets `8080`, which the edge proxies to.

#### `NEXUS_MEDIA_PROXY_READ_ONLY`

Default `false`. Refuses writes. `--read-only` can force it on.

#### `NEXUS_MEDIA_PROXY_STORAGE_BACKEND`

Default `local`. Where objects live. `local` or `s3`. Compose sets `s3`, the bundled object store.

#### `NEXUS_MEDIA_PROXY_STORAGE_ROOT`

Default `./media_proxy_storage`. The local storage directory. Used only by the local backend, so Compose does not forward it.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_MAX_BODY_BYTES`

Default `524288000`. The upload size cap on both sides. Rust accepts 1 byte to 5 GiB and refuses to start when the value is above `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_SPOOL_MAX_TOTAL_BYTES`. The effective cap is the smaller of the token's value and this.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_TOKEN_TTL_SECS`

Default `900`. Relay token lifetime. Read by the API alone.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_ENDPOINT`

Default `http://localhost:8088/media`. The relay URL handed to clients. Node side only. A trailing slash and a trailing `/v1/relay` are stripped. Compose forwards it from `.env`, and builds it from the public origin and `/media` when it is unset.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_KEEP_DIRECT_COUNTRIES`

Default empty. Countries that upload directly to S3. Node side only. Empty means every client uses the relay, which is what keeps the internal S3 address out of browsers.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_S3_TIMEOUT_MS`

Default `900000`. Relay upload timeout. Accepts 1000 to 3600000.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_BUFFERED_RETRY_BYTES`

Default `33554432`, 32 MiB. The largest declared upload the relay holds in memory so it can retry the S3 write. Accepts 0 to 268435456. A larger upload is streamed to S3 and gets no retry.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_BUFFERED_RETRY_TOTAL_BYTES`

Default `536870912`, 512 MiB. The memory all buffered relay uploads may hold at once. Accepts 0 to 8589934592. An upload that would pass it is streamed instead. The default equals the `512mb` that `NEXUS_MEDIA_PROXY_MEMORY_LIMIT` gives `media-proxy`. Lower this or raise that limit when many uploads arrive at once.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_SPOOL_DIR`

Defaults to the system temporary directory. Where relay bodies spool, and where `media-proxy` copies a stored audio or video object above 500 MiB when it has to read inside the file. That happens when the API asks for the media metadata or a frame of an upload or a stored object, and when an attachment read asks for a frame of a video. Must be writable.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_SPOOL_CHUNK_BYTES`

Default `1048576`. Spool chunk size. Accepts 64 KiB to 64 MiB.

#### `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_SPOOL_MAX_TOTAL_BYTES`

Default `8589934592`. Total spool ceiling, shared by relay bodies and the copies of stored audio and video above 500 MiB. A relay upload that does not fit beside the copies in progress fails. An upload larger than the ceiling is stored as a plain file without media metadata, and a stored video larger than the ceiling has no poster frame. Accepts 0 to 256 GiB, and must be at or above `NEXUS_MEDIA_PROXY_UPLOAD_RELAY_MAX_BODY_BYTES`, which puts the usable floor at 500 MiB by default.

Sending an audio or video attachment above 500 MiB holds up to three copies of it on local disk at once. `media-proxy` holds one in the spool directory, and `api` holds the download and the copy it rewrites without metadata in its temporary directory. Leave free space of three times the attachment size limit for each send you expect at the same moment.

`api` waits 30 seconds for the metadata of an upload up to 500 MiB. Above that it waits 30 seconds plus one second for each 16 MiB of the upload, about 94 seconds for 1 GiB and 542 seconds for 8 GiB. In that time `media-proxy` copies the upload out of object storage, reads it, and hashes it. A deployment that cannot sustain 16 MiB per second through those steps stores the upload as a plain file.

#### `NEXUS_MEDIA_PROXY_MAX_NATIVE_TRANSFORMS`

Defaults to available parallelism, clamped to 2 to 8. Concurrent image transforms. Accepts 1 to 128.

#### `NEXUS_MEDIA_PROXY_WORKER_QUEUE_CAPACITY`

Defaults to eight times the transform limit. Transform queue depth. Accepts 1 to 8192.

#### `NEXUS_MEDIA_PROXY_TRANSFORM_CACHE_BYTES`

Default `268435456`. Transform cache size. Accepts 0 to 4 GiB.

#### `NEXUS_MEDIA_PROXY_TRANSFORM_CACHE_MAX_ENTRY_BYTES`

Default `67108864`. Largest cacheable result. Accepts 0 to 512 MiB.

#### `NEXUS_MEDIA_PROXY_TRANSFORM_CACHE_TTL_MS`

Default `120000`. Transform cache lifetime. Accepts 0 to 3600000.

#### `NEXUS_MEDIA_PROXY_SOCKET_IO_TIMEOUT_MS`

Default `30000`. Socket read and write timeout. Accepts 0 to 300000.

#### `NEXUS_MEDIA_PROXY_SHUTDOWN_GRACE_MS`

Default `30000`. Milliseconds allowed to finish requests and media transforms after SIGTERM or Ctrl-C. Accepts 0 to 300000. Exceeding the deadline exits the process with an error.

#### `NEXUS_MEDIA_PROXY_TRANSFORM_TIMEOUT_MS`

Default `15000`. Per-transform timeout. Accepts 1000 to 120000.

#### `NEXUS_MEDIA_PROXY_MAX_ENCODE_FRAMES`

Default `20000`. Animation frame ceiling. Accepts 1 to 100000.

#### `NEXUS_MEDIA_PROXY_MAX_ENCODE_DURATION_MS`

Default `30000`. Animation duration ceiling. Accepts 100 to 600000.

#### `NEXUS_NSFW_SERVICE_ENDPOINT`

Default empty. An external NSFW classifier. No such service ships with the stack.

#### `NEXUS_MEDIA_PROXY_NSFW_THRESHOLD`

Default `0.85`. The media-side NSFW cutoff. Accepts 0.0 to 1.0 and finite.

#### `NEXUS_MEDIA_PROXY_CORS_MODE`

Default `off`. The [cross-origin read policy](/media-proxy/overview/#cross-origin-reads). `off`, `report`, or `enforce`. Anything else is a startup error. `report` logs each read whose origin would be refused and changes no response. `enforce` refuses those reads with 403 and sets `Access-Control-Allow-Origin` to the request origin. When `NEXUS_MEDIA_PROXY_MODE` is `static` or `relay`, the Media Proxy ignores it. In those modes a bad value is no startup error.

#### `NEXUS_MEDIA_PROXY_CORS_ALLOWED_ORIGINS`

Default empty. Comma-separated origins that may read media through CORS, such as `https://chat.example.com`. Spaces around an entry and empty entries are ignored. Each entry is parsed as a URL and must be `http` or `https` with no credentials, query, fragment, or path beyond `/`. Its host must be an IPv4 address, a bracketed IPv6 address, or a domain name whose labels are ASCII letters, digits, and hyphens after parsing. So a wildcard such as `https://*.example.com`, a brace pattern, an underscore, a trailing dot on a domain name, or any non-ASCII character fails. Write an internationalised domain name in its punycode form. The one exception is the desktop app origin `nexus-app://app`. It is accepted as an entry and is always allowed without one. Any failing entry makes the process exit. An entry is compared in the form a browser sends. `https://Chat.Example.Com:443/` matches `https://chat.example.com`. Required when `NEXUS_MEDIA_PROXY_CORS_MODE` is `report` or `enforce`. When the policy is `report` or `enforce`, the Media Proxy logs the parsed list once at startup. When `NEXUS_MEDIA_PROXY_MODE` is `static` or `relay`, the Media Proxy ignores it.

Compose forwards it from `.env`, and defaults it to the public origin, built from `NEXUS_PUBLIC_ORIGIN`, or from `NEXUS_PUBLIC_SCHEME`, `NEXUS_DOMAIN`, and `NEXUS_PUBLIC_PORT`. That origin is the only entry. The web app on the instance can then read its media. A value set in `.env` replaces the Compose value and must name the public origin.

#### `NEXUS_MEDIA_PROXY_ATTACHMENT_SIGNATURE_MODE`

Default `off`. The [signed attachment URL policy](/media-proxy/overview/#signed-attachment-urls). `off`, `report`, or `enforce`. An empty value means `off`, and anything else is a startup error. `report` logs each attachment read `enforce` would refuse and serves it. `enforce` refuses those reads with 404. Under both, a read whose signature is valid gets a `Cache-Control` lifetime that ends when the signature expires. `report` and `enforce` require `NEXUS_MEDIA_PROXY_ATTACHMENT_URL_SECRETS_BASE64`, and the Media Proxy logs the mode and the number of secrets once at startup. When `NEXUS_MEDIA_PROXY_MODE` is `static` or `relay`, the Media Proxy ignores it and the secrets. In those modes a bad value is no startup error. A self-hosted instance leaves it `off`, and signs nothing, until an operator turns it on.

Apply a change with `docker compose up -d media-proxy`. A cache or proxy in front of the instance has a switch of its own, and [Turning the signature policy on](/operator/reverse-proxy/#turning-the-signature-policy-on) gives the order to move the two in and what each pairing serves.

#### `NEXUS_GATEWAY_PRESENCE_PUSH_BUFFER_MAX_ENTRIES`

Default `128`. Presence push buffer depth.

Default `1048576`. Presence push buffer size.

#### `NEXUS_GATEWAY_PUSH_ENROLLED_CLEAR_NOTIFICATIONS_ENABLED`

Default `6`. Failures before the API circuit opens. Integer.

#### `NEXUS_GATEWAY_HTTP_RECOVERY_TIMEOUT_MS`

Default `15000`. How long the circuit stays open. Milliseconds.

#### `NEXUS_GATEWAY_CLUSTER_ENABLED`

Default `false`. BEAM clustering. Single-node by default. Compose forwards none of the clustering names, because the stack runs one Gateway node.

#### `NEXUS_GATEWAY_CLUSTER_DISCOVERY_DNS_NAME`

No default. The DNS name peers are discovered through. Needs clustering on.

#### `NEXUS_GATEWAY_CLUSTER_DISCOVERY_NODE_BASENAME`

No default. The node basename for discovery. Needs clustering on.

#### `NEXUS_GATEWAY_CLUSTER_DISCOVERY_POLL_INTERVAL_MS`

Default `5000`. Discovery poll interval. Milliseconds.

#### `NEXUS_GATEWAY_CLUSTER_STATIC_PEERS`

Default empty. A fixed peer list. Comma separated Erlang node names, capped at 256. An entry that is not a node name fails startup.

#### `NEXUS_ERLANG_NODE_NAME`

Default `nexus_gateway@127.0.0.1`. The BEAM node name. Must be resolvable by peers when clustering. Compose does not forward it.

#### `NEXUS_ERLANG_COOKIE`

No default. The BEAM distribution secret. The Gateway refuses to start without it, and Compose refuses to start the stack when `.env` lacks it. Anyone who reaches the distribution port with the value gets code execution, so keep the port unpublished.

#### `NEXUS_ERLANG_DIST_PORT`

Default `8081`. The BEAM distribution port. Not published or forwarded by Compose. Never expose it.

#### `NEXUS_ERLANG_SCHEDULERS`

Defaults to the container CPU count, clamped to 2 through 16. Normal scheduler count. Positive integer, passed to the BEAM as `+S N:N`. A value that is not a positive integer is ignored and the derivation runs instead.

#### `NEXUS_ERLANG_DIRTY_CPU_SCHEDULERS`

Defaults to two thirds of the scheduler count, rounded up. Dirty CPU scheduler count. Positive integer, passed as `+SDcpu N:N`. Same fallback rule as `NEXUS_ERLANG_SCHEDULERS`.

#### `NEXUS_ERLANG_SCHEDULERS_MIN`

Default `2`. The floor of the scheduler clamp.

#### `NEXUS_ERLANG_SCHEDULERS_MAX`

Default `16`. The ceiling of the scheduler clamp. `.env.example` ships both names commented out.

The Gateway entrypoint derives the scheduler counts before the BEAM starts. It reads the container CPU quota, clamps the result between `NEXUS_ERLANG_SCHEDULERS_MIN` and `NEXUS_ERLANG_SCHEDULERS_MAX`, exports the answer as `NEXUS_ERLANG_SCHEDULERS`, and derives `NEXUS_ERLANG_DIRTY_CPU_SCHEDULERS` from it. `vm.args.src` then substitutes both into `+S` and `+SDcpu`.

Setting `NEXUS_ERLANG_SCHEDULERS` pins the count and skips the clamp.

The Gateway protocol version is `1`. The Gateway answers any other value in `?v=` with 101, then a close frame reading `Invalid API version`. [Gateway overview](/gateway/overview/) has the close code.

## Content Security Policy

`app-proxy` builds the policy for the client HTML and the assets it serves. The client HTML policy allows each inline script by its SHA-256 hash. Each variable appends sources to one directive on top of the built-in ones. All are empty by default. Apply a change with `docker compose up -d app-proxy`.

`NEXUS_CSP_EXTRA_DEFAULT_SRC`, `NEXUS_CSP_EXTRA_CONNECT_SRC`, `NEXUS_CSP_EXTRA_IMG_SRC`, `NEXUS_CSP_EXTRA_MEDIA_SRC`, `NEXUS_CSP_EXTRA_FONT_SRC`, `NEXUS_CSP_EXTRA_SCRIPT_SRC`, `NEXUS_CSP_EXTRA_STYLE_SRC`, `NEXUS_CSP_EXTRA_FRAME_SRC`, `NEXUS_CSP_EXTRA_WORKER_SRC`, and `NEXUS_CSP_EXTRA_MANIFEST_SRC` take one or more sources separated by commas, spaces, tabs, or newlines. Blank entries and sources the directive already lists are dropped. `NEXUS_CSP_REPORT_URI` sets a single `report-uri` value.

`object-src`, `base-uri`, and `frame-ancestors` are fixed and have no override. `app-proxy` adds the static CDN endpoint and the media endpoint from its environment. The self-hosted image also adds the origin of each branding image to `img-src`. At start it takes them from `NEXUS_APP_ICON_URL`, `NEXUS_APP_SYMBOL_URL`, `NEXUS_APP_LOGO_URL`, `NEXUS_APP_WORDMARK_URL` and `NEXUS_APP_FAVICON_URL`. It then polls the discovery document every `DISCOVERY_REFRESH_INTERVAL_MS`, where a value saved in the admin dashboard wins. A dashboard change reaches the header within a minute by default with no restart. A stack on one hostname needs no extra sources. The usual reason to set one is a voice server on another hostname, which needs its WebSocket origin in `NEXUS_CSP_EXTRA_CONNECT_SRC`. [Voice media does not use the proxy](/operator/reverse-proxy/#voice-media-does-not-use-the-proxy) has that line in place.

A front proxy must not add a [Content-Security-Policy of its own](/operator/reverse-proxy/#send-no-content-security-policy-of-its-own).

#### Instance Config, Community & Policy

Single-community mode, direct messages and friends, the premium model, and optional embed services.

#### Instance Config, Runtime Integrations

#### Instance Config, Premium & billing

The premium tier name and information link, the billing switch, the Stripe secret key and webhook secret, the webhook URL to register in Stripe, and the price catalogue with its default currency, country currencies and legacy prices. See [Payments](#payments).

#### Instance Config, Media Expiry

Size-based attachment lifetimes. The built-in default is on.

Turning expiry off hides every expiry date at once and stops deletion. The stored dates are kept.

On a self-hosted instance, changes also apply to attachments that were uploaded earlier. Turning expiry on, or changing a size or lifetime rule, starts a background job that works through existing messages in chunks and recalculates the expiry of their attachments. No attachment is deleted while that job runs. An attachment whose date passed while expiry was off, or that the new settings would expire sooner, is kept for at least the renew window first. Until the job reaches a message, its attachments show the state they had before, so one whose date passed while expiry was off shows as expired until then.

The official hosted instance does not run that job. There, a change applies to attachments uploaded from then on, and deletion of expired attachments is never paused.

#### Instance Config, Gateway Rollout Configuration

Session and guild rollout percentages, RPC timeouts, and Gateway concurrency.

#### Instance Config, Single Sign-On (SSO)

OIDC-style SSO for the client and admin apps, and whether SSO is enforced.

#### Limit Config

The [instance limits](/http-api/instance/#limit-configuration-object) published to clients.

#### Voice Regions and Voice Servers

The voice regions offered and the servers behind them.

#### Admin API Keys

Credentials for the [Admin API](/admin-api/).

These settings exist only in the dashboard: attachment decay, which defaults to on, and the inactivity deletion threshold, which defaults to 365 days.

Most settings reach `api`, `worker`, `gateway`, `media-proxy`, `push`, `admin` and the internal services through one shared environment block, so one line in `.env` reaches every one of them that reads it. `app-proxy` takes its own list, since it reads the static, media and S3 upload origins, the branding image URLs and its own names. The internal services each run a router, which takes requests and holds no state, and one shard, which holds the caches and the database connections. The shipped stack fixes `NEXUS_SVC_SHARD_COUNT` at `1`.

## Resources

Every service has a memory limit and four also have a memory reservation, all under `deploy.resources`. Compose reads `gb` as 1024 MiB and `mb` as 1 MiB, so `5gb` is 5368709120 bytes. Plain `docker compose up` applies both keys on a single host, with no Swarm and no `--compatibility` flag. The engine rejects any limit below `6mb`, and rejects a limit lower than the same service's reservation with `Minimum memory limit can not be less than memory reservation limit`.

A limit is a ceiling. The limits below sum to 18.5 GiB and the stack does not need a host that large, because each container uses only the memory it allocates, up to its limit.

`deploy.resources.reservations.memory` becomes the container's cgroup v2 `memory.low`, which biases kernel reclaim towards other containers under host pressure. It reserves nothing on its own.

All are optional.

#### `NEXUS_CADDY_MEMORY_LIMIT`

Default `256mb`. The ceiling for `edge`.

#### `NEXUS_POSTGRES_MEMORY_LIMIT`

Default `5gb`. The ceiling for `postgres`. Must be at or above `NEXUS_POSTGRES_MEMORY_RESERVATION` or the container fails to create. Shared memory in use under `NEXUS_POSTGRES_SHM_SIZE` is charged against it.

#### `NEXUS_VALKEY_MEMORY_LIMIT`

Default `256mb`. The ceiling for `valkey`. Must stay above `NEXUS_VALKEY_MAXMEMORY`, which bounds the stored dataset alone.

#### `NEXUS_NATS_MEMORY_LIMIT`

Default `256mb`. The ceiling for `nats`. Covers JetStream file store metadata as well as the core server.

#### `NEXUS_MEILISEARCH_MEMORY_LIMIT`

Default `1536mb`. The ceiling for `meilisearch`. Indexing a backlog of a few hundred thousand messages with two indexing threads peaks near 1 GB, so keep this above 1 GB.

#### `NEXUS_MEILISEARCH_MAX_INDEXING_MEMORY`

Default `256mb`. Becomes `MEILI_MAX_INDEXING_MEMORY`. The memory the indexer may use for one batch. Meilisearch uses more than this while indexing, because every indexing thread also has buffers of its own. Lower it whenever you lower `NEXUS_MEILISEARCH_MEMORY_LIMIT`.

#### `NEXUS_MEILISEARCH_MAX_INDEXING_THREADS`

Default `2`. Becomes `MEILI_MAX_INDEXING_THREADS`. Without it Meilisearch indexes on half the host's CPU threads, and each thread can use up to 150 MB of buffers, so a host with many cores runs out of memory under a container limit that suits a small one. Raise it only together with `NEXUS_MEILISEARCH_MEMORY_LIMIT`.

#### `NEXUS_MEILISEARCH_ENV`

Default `production`. Becomes `MEILI_ENV`. `production` requires the master key on every request.

#### `NEXUS_MEILISEARCH_NO_ANALYTICS`

Default `true`. Becomes `MEILI_NO_ANALYTICS`, which keeps Meilisearch from sending usage data.

#### `NEXUS_SEAWEEDFS_MEMORY_LIMIT`

Default `2gb`. The ceiling for `seaweedfs`. One process runs the master, the volume server and the S3 gateway. The peak is the parts of one upload in flight at once, which the client uploads in parallel: a 500 MB attachment is 20 parts of 25 MB.

#### `NEXUS_SEAWEEDFS_GOMEMLIMIT`

Default `1536MiB`. The heap ceiling the Go runtime collects against. Go cannot see the container limit, so without this value an upload burst grows the heap past `NEXUS_SEAWEEDFS_MEMORY_LIMIT` and the kernel OOM-kills the container mid-upload with exit 137. Raising `NEXUS_SEAWEEDFS_MEMORY_LIMIT` on its own does not fix that, because the runtime grows to fill whatever it is given. Keep this near three quarters of the container limit and move the two together.

#### `NEXUS_SEAWEEDFS_TELEMETRY`

Default `false`. Becomes the `-master.telemetry` flag of `seaweedfs`, which reports usage to the SeaweedFS project when on.

#### `NEXUS_SEAWEEDFS_VOLUME_GROWTH`

Default `1`. Becomes `WEED_MASTER_VOLUME_GROWTH_COPY_1`, the number of volumes SeaweedFS creates at once when a bucket runs out of room. Each volume reserves a 1 GB slot of free disk, and the stack writes to four buckets. SeaweedFS's own default of 7 needs about 28 GB free before every bucket has a volume, so on a smaller disk the first bucket takes every slot and uploads fail with `No writable volumes and no free volumes left`.

#### `NEXUS_SEAWEEDFS_INIT_MEMORY_LIMIT`

Default `128mb`. The ceiling for `seaweedfs-init`. A one-shot container that exits, so it never overlaps steady state.

#### `NEXUS_LIVEKIT_MEMORY_LIMIT`

Default `512mb`. The ceiling for `livekit`. Grows with the number of concurrent voice publishers.

#### `NEXUS_API_MEMORY_LIMIT`

Default `2560mb`. The ceiling for `api`. Node derives its heap ceiling from this at about half, and the derivation stops falling at or below `512mb`.

#### `NEXUS_WORKER_MEMORY_LIMIT`

Default `2560mb`. The ceiling for `worker`. Same Node derivation as `api`, applied to every background lane at once.

#### `NEXUS_GATEWAY_MEMORY_LIMIT`

Default `1gb`. The ceiling for `gateway`. The BEAM has no heap ceiling of its own, so this limit is the only bound on the Gateway.

#### `NEXUS_MEDIA_PROXY_MEMORY_LIMIT`

Default `512mb`. The ceiling for `media-proxy`. Image and video transforms decode into this ceiling, so a large upload is what reaches this limit.

#### `NEXUS_PUSH_MEMORY_LIMIT`

Default `256mb`. The ceiling for `push`. Raise it alongside `NEXUS_PUSH_SERVICE_QUEUE_CAPACITY` or `NEXUS_PUSH_SERVICE_SEND_CONCURRENCY`.

#### `NEXUS_STATIC_PROXY_MEMORY_LIMIT`

Default `256mb`. The ceiling for `static-proxy`. The service reads no environment variables and serves files only.

#### `NEXUS_APP_PROXY_MEMORY_LIMIT`

Default `256mb`. The ceiling for `app-proxy`. It keeps the branding image origins from discovery in memory and reads no database.

#### `NEXUS_SNOWFLAKES_MEMORY_LIMIT`

Default `128mb`. The ceiling for `snowflakes`. A router holds no shard state.

#### `NEXUS_SNOWFLAKES_SHARD_MEMORY_LIMIT`

Default `256mb`. The ceiling for `snowflakes-shard`. Holds the identifier buffer sized by `NEXUS_SNOWFLAKE_SERVICE_BATCH_SIZE`.

#### `NEXUS_USERS_MEMORY_LIMIT`

Default `128mb`. The ceiling for `users`. A router holds no shard state.

#### `NEXUS_USERS_SHARD_MEMORY_LIMIT`

Default `256mb`. The ceiling for `users-shard`. Holds the read cache bounded by `NEXUS_SVC_CACHE_MAX_ENTRIES`, which defaults to 100000 entries.

#### `NEXUS_GIFS_MEMORY_LIMIT`

Default `128mb`. The ceiling for `gifs`. A router holds no shard state.

#### `NEXUS_GIFS_SHARD_MEMORY_LIMIT`

Default `256mb`. The ceiling for `gifs-shard`. Lower than the 536870912 byte default of `NEXUS_GIFS_SHARD_CACHE_MAX_BYTES`.

#### `NEXUS_MESSAGES_MEMORY_LIMIT`

Default `128mb`. The ceiling for `messages`. A router holds no shard state.

#### `NEXUS_MESSAGES_SHARD_MEMORY_LIMIT`

Default `256mb`. The ceiling for `messages-shard`. The shard has a Postgres pool of 20 connections alongside the read cache.

#### `NEXUS_UNFURL_MEMORY_LIMIT`

Default `128mb`. The ceiling for `unfurl`. A router holds no shard state.

#### `NEXUS_UNFURL_SHARD_MEMORY_LIMIT`

Default `256mb`. The ceiling for `unfurl-shard`. Fetches remote pages, so a slow upstream holds bytes for the length of the fetch.

#### `NEXUS_ADMIN_MEMORY_LIMIT`

Default `256mb`. The ceiling for `admin`. Serves the dashboard and proxies no media.

A reservation goes to the services whose loss takes the instance down, so the kernel reclaims from everything else first. All are optional.

#### `NEXUS_POSTGRES_MEMORY_RESERVATION`

Default `3gb`. The reclaim floor for `postgres`. Must be at or below `NEXUS_POSTGRES_MEMORY_LIMIT`. Lowering the limit alone fails container creation.

#### `NEXUS_API_MEMORY_RESERVATION`

Default `1gb`. The reclaim floor for `api`. Must be at or below `NEXUS_API_MEMORY_LIMIT`.

#### `NEXUS_WORKER_MEMORY_RESERVATION`

Default `1gb`. The reclaim floor for `worker`. Must be at or below `NEXUS_WORKER_MEMORY_LIMIT`.

#### `NEXUS_GATEWAY_MEMORY_RESERVATION`

Default `384mb`. The reclaim floor for `gateway`. Must be at or below `NEXUS_GATEWAY_MEMORY_LIMIT`.

Node sizes its own old-space heap at roughly half the container limit, with a floor near 259 MB. A container limit of `2560mb` gives a 1328 MB heap ceiling, `1280mb` gives 664 MB, `768mb` gives 396 MB, and every limit at or under `512mb` gives the same 259 MB. Pin the value only to move it away from that derivation. All are optional.

#### `NEXUS_API_NODE_HEAP_MB`

No default. The V8 old-space ceiling for `api`, in MB. Appended to `NODE_OPTIONS` as `--max-old-space-size` only when non-empty. Keep it below `NEXUS_API_MEMORY_LIMIT`.

#### `NEXUS_WORKER_NODE_HEAP_MB`

No default. The V8 old-space ceiling for `worker`, in MB. Same rule against `NEXUS_WORKER_MEMORY_LIMIT`.

#### `NEXUS_API_NODE_OPTIONS`

No default. Extra Node flags for `api`, such as `--dns-result-order=ipv4first`. Compose reads it from `.env` and appends it to `NODE_OPTIONS` after `--enable-source-maps` and the heap flag, only when non-empty.

#### `NEXUS_WORKER_NODE_OPTIONS`

No default. Extra Node flags for `worker`. Same rule as `NEXUS_API_NODE_OPTIONS`.

The names on the Postgres command line tune the bundled server. Keep them consistent with `NEXUS_POSTGRES_MEMORY_LIMIT`. All are optional.

#### `NEXUS_POSTGRES_SERVER_MAX_CONNECTIONS`

Default `150`. The server-wide connection ceiling. The shipped pools total 90, from 25 each for `api` and `worker` and 20 each for `messages-shard` and `users-shard`. A value under about 95 exhausts the server before the pools fill, and the connections it turns away are refused with `too many clients already`.

#### `NEXUS_POSTGRES_SHARED_BUFFERS`

Default `512MB`. The shared buffer pool. Allocated at server start, so it is charged to the container whether or not it is used.

#### `NEXUS_POSTGRES_EFFECTIVE_CACHE_SIZE`

Default `2GB`. The planner's assumption about disk cache. Allocates nothing. Lowering it makes the planner prefer sequential scans and frees no memory.

#### `NEXUS_POSTGRES_WORK_MEM`

Default `8MB`. The per-operation sort and hash budget. Charged per sort or hash node, so one complex query can spend several multiples of it.

#### `NEXUS_POSTGRES_MAINTENANCE_WORK_MEM`

Default `256MB`. The budget for one VACUUM, CREATE INDEX, or ALTER TABLE. One such operation at a time normally holds it.

#### `NEXUS_POSTGRES_AUTOVACUUM_WORK_MEM`

Default `128MB`. The budget for each autovacuum worker. Postgres runs three workers by default, so budget three times this value.

#### `NEXUS_POSTGRES_SHM_SIZE`

Default `1gb`. The shared memory of the `postgres` container, used by parallel queries and parallel maintenance. Keep it well above `NEXUS_POSTGRES_MAINTENANCE_WORK_MEM`. A manual VACUUM sizes its shared memory from that budget, and fails with `could not resize shared memory segment` when it does not fit.

The rest of the Postgres command line has one variable per setting.

- `NEXUS_POSTGRES_RANDOM_PAGE_COST`: default `1.1`, sets `random_page_cost`.
- `NEXUS_POSTGRES_EFFECTIVE_IO_CONCURRENCY`: default `200`, sets `effective_io_concurrency`.
- `NEXUS_POSTGRES_DEFAULT_STATISTICS_TARGET`: default `200`, sets `default_statistics_target`.
- `NEXUS_POSTGRES_JIT`: default `off`, sets `jit`.
- `NEXUS_POSTGRES_MIN_WAL_SIZE`: default `512MB`, sets `min_wal_size`.
- `NEXUS_POSTGRES_MAX_WAL_SIZE`: default `2GB`, sets `max_wal_size`.
- `NEXUS_POSTGRES_CHECKPOINT_COMPLETION_TARGET`: default `0.9`, sets `checkpoint_completion_target`.
- `NEXUS_POSTGRES_WAL_BUFFERS`: default `16MB`, sets `wal_buffers`.
- `NEXUS_POSTGRES_WAL_COMPRESSION`: default `zstd`, sets `wal_compression`.
- `NEXUS_POSTGRES_BGWRITER_DELAY`: default `50ms`, sets `bgwriter_delay`.
- `NEXUS_POSTGRES_BGWRITER_LRU_MAXPAGES`: default `1000`, sets `bgwriter_lru_maxpages`.
- `NEXUS_POSTGRES_AUTOVACUUM_VACUUM_SCALE_FACTOR`: default `0.05`, sets `autovacuum_vacuum_scale_factor`.
- `NEXUS_POSTGRES_AUTOVACUUM_ANALYZE_SCALE_FACTOR`: default `0.02`, sets `autovacuum_analyze_scale_factor`.
- `NEXUS_POSTGRES_AUTOVACUUM_VACUUM_COST_LIMIT`: default `2000`, sets `autovacuum_vacuum_cost_limit`.
- `NEXUS_POSTGRES_TRACK_IO_TIMING`: default `on`, sets `track_io_timing`.
- `NEXUS_POSTGRES_SHARED_PRELOAD_LIBRARIES`: default `pg_stat_statements`, sets `shared_preload_libraries`.

`shared_preload_libraries` is read only when the server starts. Add a library only if the image ships it, or Postgres refuses to start.

The bundled Valkey uses persistent storage. These settings control its memory limit, its behaviour when full, and how often it writes to disk.

#### `NEXUS_VALKEY_MAXMEMORY`

Default `192mb`. The dataset ceiling. Bounds stored keys only. Client buffers, replication buffers and allocator overhead sit outside it and inside `NEXUS_VALKEY_MEMORY_LIMIT`.

#### `NEXUS_VALKEY_MAXMEMORY_POLICY`

Default `noeviction`. An over-limit write returns an OOM error. Keep this policy to protect deletion queues and other shared state. See [Volumes and buckets](#volumes-and-buckets) for recovery implications.

#### `NEXUS_VALKEY_APPENDFSYNC`

Default `everysec`. How often Valkey flushes its append-only file to disk. `always`, `everysec` or `no`. `everysec` can lose the last second of writes in a crash.

No service sets a CPU limit, a CPU reservation or `cpu_shares`, so every container sees the host's full CPU count. Bound the Gateway's scheduler count with `NEXUS_ERLANG_SCHEDULERS_MIN` and `NEXUS_ERLANG_SCHEDULERS_MAX`, or pin it with `NEXUS_ERLANG_SCHEDULERS` and `NEXUS_ERLANG_DIRTY_CPU_SCHEDULERS` from [Gateway settings](#gateway-settings).

On a host smaller than the 16 GB the defaults assume, lower the large ceilings and the Postgres tuning together. The block below is the 8 GB profile.

```bash
NEXUS_POSTGRES_MEMORY_LIMIT=2560mb
NEXUS_POSTGRES_MEMORY_RESERVATION=1gb
NEXUS_POSTGRES_SHARED_BUFFERS=384MB
NEXUS_POSTGRES_EFFECTIVE_CACHE_SIZE=1536MB
NEXUS_API_MEMORY_LIMIT=1280mb
NEXUS_API_MEMORY_RESERVATION=768mb
NEXUS_WORKER_MEMORY_LIMIT=1280mb
NEXUS_WORKER_MEMORY_RESERVATION=768mb
NEXUS_GATEWAY_MEMORY_LIMIT=512mb
NEXUS_GATEWAY_MEMORY_RESERVATION=256mb
NEXUS_MEILISEARCH_MEMORY_LIMIT=1gb
NEXUS_MEILISEARCH_MAX_INDEXING_MEMORY=192mb
NEXUS_SEAWEEDFS_MEMORY_LIMIT=1gb
NEXUS_SEAWEEDFS_GOMEMLIMIT=768MiB
NEXUS_GIFS_SHARD_CACHE_MAX_BYTES=134217728
```

At 8 GB the api and worker heap ceilings fall to 664 MB each and Postgres caches less of the working set, which shows up as slower search and slower history scrolling under load. Nothing is turned off, though the largest attachments need the default `2gb` SeaweedFS ceiling to upload every part at once.

The 4 GB profile trades more.

NEXUS_WORKER_MEMORY_LIMIT=640mb
NEXUS_WORKER_MEMORY_RESERVATION=384mb

## Health checks and restarts

Compose reads these, and no NEXUS service does. The health checks decide when a dependent service may start and when Docker marks a container unhealthy. All are optional.

- `NEXUS_RESTART_POLICY`: default `unless-stopped`, for every long-running service. `seaweedfs-init` never restarts.
- `NEXUS_HEALTHCHECK_INTERVAL`: default `10s`, for every check.
- `NEXUS_HEALTHCHECK_TIMEOUT`: default `5s`, for every check.
- `NEXUS_HEALTHCHECK_RETRIES`: default `10`, for `edge`, `postgres`, `valkey`, `nats`, `meilisearch`, `livekit` and `static-proxy`.
- `NEXUS_APP_HEALTHCHECK_RETRIES`: default `30`, for the internal services, `api`, `gateway`, `push` and `admin`.
- `NEXUS_APP_HEALTHCHECK_START_PERIOD`: default `90s`, for `api`, `worker` and `gateway`.
- `NEXUS_SVC_HEALTHCHECK_START_PERIOD`: default `60s`, for the internal services, `push` and `admin`.
- `NEXUS_WORKER_HEALTHCHECK_RETRIES`: default `3`, for `worker`. Its check reads a heartbeat file, and a stale one means the worker is stuck.
- `NEXUS_SEAWEEDFS_HEALTHCHECK_RETRIES`: default `20`, for `seaweedfs`.
- `NEXUS_SEAWEEDFS_HEALTHCHECK_START_PERIOD`: default `60s`, for `seaweedfs`. `api`, `worker` and `media-proxy` wait on `seaweedfs-init`, which waits on this check.
- `NEXUS_SEAWEEDFS_INIT_ATTEMPTS`: default `60`. Compose forwards it from `.env` to `seaweedfs-init`, which checks and creates the buckets that many times, 2 seconds apart, before it gives up. Raise it when `docker compose up` fails on `seaweedfs-init` on a slow disk.

Durations take the Compose form, such as `90s` or `2m`. Raise the retries or start period on a slow host where a service is still starting when its check gives up.

## Routing

The edge is the only HTTP entry point, and every route is served from the one public hostname. It rewrites each path before handing it to an upstream. [What the single port routes](/operator/reverse-proxy/#what-the-single-port-routes) has the path table, and [What every proxy must do](/operator/reverse-proxy/#what-every-proxy-must-do) has the requirements for anything in front of the edge.

`NEXUS_ADMIN_BASE_PATH` moves the admin path, and no other variable on this page changes that routing. The `Caddyfile` is a bind mount, so an edit to it takes `docker compose restart edge`.

CORS origins are exactly the app endpoint, the `NEXUS_APP_ORIGIN_ALIASES` origins, and the marketing endpoint. Serving the client from a hostname other than `NEXUS_DOMAIN` requires overriding `NEXUS_APP_ENDPOINT`.

## Volumes and buckets

| Volume | Holds | Back up |
| --- | --- | --- |
| postgres-data | Every account, message, and configuration row | Yes |
| seaweedfs-data | Every uploaded file | Yes |
| valkey-data | Pending file deletions, the thread auto archive schedule, other queues and shared cache | Yes |
| nats-data | Pending and failed background jobs | Yes |
| edge-data | Issued TLS certificates | Optional, a loss only costs a re-issue |
| edge-config | The edge's own state | No |
| meilisearch-data | The search index, rebuildable from Postgres | Optional |

Losing `valkey-data` can delay scheduled account and bulk-message deletions while their queues are rebuilt. Pending asset deletions and cache purges exist only here and are lost with it, so do not treat this volume as disposable cache. The thread auto archive schedule exists only here too. After a loss, an active thread is archived automatically again only once it is modified or unarchived. [Thread lifecycle](/http-api/threads/#thread-lifecycle) states the archive rule.

Losing `meilisearch-data` leaves search empty until it is rebuilt. Nothing rebuilds it automatically, because Postgres still records every channel as indexed. Rebuild each index with [`POST /admin/search/indexes/{index_name}/refreshes`](/admin-api/search-indexes/). The `channel_messages`, `guild_members` and `threads` indexes rebuild one community at a time and need a `guild_id` for each. A backup of the volume avoids those calls on a large instance.

`nats-data` retains pending jobs in `JOBS` for up to 7 days and failed jobs in `JOBS_DLQ` for up to 30 days. A full jobs stream rejects new work. A full dead-letter stream drops its oldest entries, so investigate failures promptly. If dead-letter storage is unavailable, failed jobs remain in `JOBS` only until they expire. Losing this volume loses queued work, which is not automatically recovered from the database.

Startup refuses an existing `JOBS` or `JOBS_DLQ` stream with the wrong name, subjects, retention or storage type, or with sealing, no-ack, mirroring, sources, republishing or a subject transform set. Startup never recreates a stream. When the `JOBS` limits differ, startup updates them in place, unless tightening them would drop queued jobs. Stop publishers and workers before migrating an incompatible stream.

Volume names are prefixed with the Compose project name, so `postgres-data` is `nexus_postgres-data` on the host.

`seaweedfs-init` creates these buckets and exits. Each bucket takes its name from its variable in `.env`, and the table gives the default.

| Bucket | Set by | Holds |
| --- | --- | --- |
| nexus | `NEXUS_S3_BUCKET_CDN` | Avatars, guild and entity assets, themes, entrance sounds, memes, and processed attachments |
| nexus-uploads | `NEXUS_S3_BUCKET_UPLOADS` | Raw attachment uploads, before processing |
| nexus-reports | `NEXUS_S3_BUCKET_REPORTS` | Abuse report evidence |
| nexus-harvests | `NEXUS_S3_BUCKET_HARVESTS` | User and guild data archives |

`NEXUS_S3_BUCKET_STATIC` names an optional bucket. The shipped stack does not use or create it.
